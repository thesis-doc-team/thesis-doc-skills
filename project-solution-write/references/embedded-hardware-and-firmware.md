# MCU / 传感器 / 无线通信项目实施规则

## 一、硬件选型核算

- MCU：真实封装、Flash/SRAM、主频及工作电压、可用 USART/I²C/SPI/ADC/DMA/TIM/GPIO、调试口保留、管脚复用冲突；不要只凭型号系列推断引脚。
- 传感器：具体产品型号、供电电压、信号电平、数字地址、上拉电阻、校准、启动时间、数据有效范围、读写时序、CRC 等。
- 通信：UART TTL 与 RS232/RS485 严格区分；RS485 收发器需核对 DE/RE 自动/手动切换；Modbus 寄存器和从站地址须与实物匹配；LoRa 模组两端参数需兼容且频段符合法规。
- 供电：电源输入/稳压、峰值发射电流、隔离/保护、共地、负载驱动（蜂鸣器/电机/继电器）、室外场景防护。
- 输出引脚表：`功能/MCU 引脚/复用/方向/电平/外设参数/模块端子/状态(已确认或拟定)/依据`；精确引脚只能在 MCU 封装和接口已明确时锁定。

## 二、固件数据流

```text
GPIO/ADC/UART/I²C/RS485 驱动
    → 帧/传感器校验和量纲转换
    → {value, is_valid, last_update_ms, error_code}
    → 算法/报警/本地显示/无线载荷
```

带模拟数据时，输入路径必须与真实路径明确隔离；测试数据不能冒充实时实测结果。多模块共享数据时，使用快照或一致的读取接口，避免一帧里混用不一致的更新状态。

## 三、调度选择

- 裸机：低频、有限阻塞、简单并发可采用 SysTick 或定时器 Tick，短小的 `Process` 处理缓冲，低频的 `Tick` 触发任务。
- 中断：只做必要数据搬运与标志设置；单字节中断接收配环形缓冲。DMA RX 必须验证真正启动的 DMA 路径和重新启动条件。
- FreeRTOS：仅当多个明确独立任务的实时性、延迟、队列/同步收益大于栈和调试成本时使用，需定义任务优先级与共享数据保护。
- 阻塞函数：统计 `HAL_Delay()`、I²C/UART 超时、DMA 等待；核算最坏循环耗时及环形缓冲容量。

## 四、协议必须达到可复现程度

完整描述一条真实收发链：

`谁发 → 发送条件 → 字段 → 编码/单位 → 帧边界 → 校验 → 接收方何时处理 → 错误/超时 → UI/告警结果`。

必须核对发包端无效占位与接收端解析，Modbus 响应的地址/功能码/长度/CRC，LoRa 对端断线后的时效策略，以及任何上报成功认定的证据层级。

## 五、实施与验收

开发顺序优先为：供电/主控 → 调试口/时钟 → 单个传感器 → 数据接口 → OLED/按键 → 报警 → 无线/云链路 → 异常/压力/长稳。每一步给出可观察结果，未知的精度与可靠性只设为**拟验证目标**。
