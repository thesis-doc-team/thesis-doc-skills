# 项目介绍 HTML 质量检查

## 一、静态检查（scripts/validate_intro_html.py）

### 必失败项（FAIL）

1. 不是单文件结构：缺少 doctype、`lang="zh-CN"`、viewport；`<style>` 不是 1 个；`<script>` 不是数据块 + 逻辑块两个。
2. 依赖联网资源：外部 `<script src>`、`<link href>`、远程图片、`@import`、`url(http...)`、iframe/object/embed。
3. 安全风险：内联事件处理器、`javascript:` 链接、`innerHTML`、`document.write`、`eval`、表单。
4. 实施层泄漏：GPIO、USART、UART、I2C、SPI、DMA、CRC、ADC、PWM、Flash、EEPROM、CubeMX、AT+、寄存器、引脚、波特率、`#include`、`PA9` 类引脚名、接线图/原理图、疑似凭据、收费/售价措辞。
5. 功能不一致：HTML 功能卡片数与结构化数据不一致；HTML 出现 Markdown 中没有的功能；卡片文字缺失。
6. 场景示意没有“示意/未实测”标注。
7. 结构化数据缺失 `project.title` 或数据块无法解析。
8. 响应式断点少于 2 个。

### 警告项（WARN，需人工确认）

- 出现 MQTT、JSON、API、协议、端口、部署、代码、固件、工程实施方案等偏技术词。
- HTML 功能数与 Markdown 功能小节数不一致（可能因表格型功能清单）。
- 未发现 `auto-fit`、`max-width`、`box-sizing`、`overflow-wrap`（需人工检查长文本/多卡片）。
- 页面源码未直接出现完整项目题目（标题拆分后可能出现，需人工看 `<title>`）。
- 没有功能卡片或 Markdown 未识别到功能小节。

## 二、人工/浏览器检查

静态 PASS 只代表结构、边界和名称覆盖，**不代表视觉验收**。至少检查：

1. **桌面端**：1440px 宽截图；hero、summary、功能卡、流程、场景示意、场景卡、系统组成、页脚完整；无横向滚动。
2. **手机端**：390px 宽（可用 iframe 固定宽度规避无头浏览器最小窗口限制）；标题换行、功能卡单列、流程单列、场景单列、场景切换按钮可点、无横向溢出。
3. **动态数量**：3 个功能 / 6 个功能 / 10+ 个功能；1 个场景 / 多个场景；3 步 / 6 步流程；长标题、长描述。
4. **缺失章节**：无流程、无场景、无系统组成时不出现空标题或空卡片。
5. **交互**：场景按钮切换后标题、编号、状态、操作、预期同步更新；`aria-pressed` 正确；键盘可操作。
6. **无 JavaScript**：主要内容仍可阅读；场景默认显示第一条。
7. **打印**：导航、按钮、选择器、浮动标签隐藏，卡片不跨页拆分。
8. **内容边界**：页面没有工程实施方案的引脚/协议/代码/部署命令/收费说明；没有虚构数值或实测结论。

## 三、浏览器渲染能力

如果本机有 Chrome/Edge，可用无头模式生成桌面与移动截图：

```bash
# 桌面
"<chrome>" --headless=new --disable-gpu --hide-scrollbars \
  --virtual-time-budget=2500 --window-size=1440,3800 \
  --screenshot="desktop.png" "file:///<绝对路径>/intro.html"

# 移动：用 390px 宽 iframe 规避无头浏览器最小窗口宽度
# 或直接使用真实浏览器设备模拟
```

无头 Chrome 在 Windows 上可能强制最小窗口宽度（约 512px），直接用 `--window-size=390` 会得到“布局 512、截图 390”的裁切假象。应使用 390px 宽的 iframe 容器，或在浏览器 DevTools 设备模拟中检查。若无法进行浏览器渲染，必须在执行汇报中如实说明“未做视觉验收”，不能声称已完成。

## 四、证据与汇报

- 记录：项目、介绍 MD 路径、HTML 路径、生成器版本、功能/流程/场景/验收数量、静态检查结果、截图路径（如有）、人工检查结论。
- 静态 PASS ≠ 实机验证；页面中的“预期/未实测”标签必须保留。
- 如果只修改 HTML 样式，不得反向改写介绍 MD 或工程实施方案；如果介绍 MD 改动，重新生成 HTML 并重新跑静态与视觉检查。
