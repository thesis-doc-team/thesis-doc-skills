# 通信协议、数据时效与验收闭环

## 通信双端核对表

| 核对项目 | 必须填写 |
|---|---|
| 发送端 | 何设备、什么触发条件、收发方向 |
| 物理通道 | UART TTL/RS485/LoRa/DTU、网络端口、波特率或链路参数 |
| 完整帧 | 帧头/字段/单位/字节序/终止符、示例正确报文 |
| 错误帧 | `--`、无效标志、缺字段、错误 CRC、半帧、多帧如何处理 |
| 接收端 | 解析算法、长度限制、校验、旧值淘汰与失败恢复 |
| 送达证据 | UART TX 完成/模组状态/接收端确认/服务端回执各不等价 |
| 可靠性选择 | 单向、ACK、重传、去重、序号等根据需要选择及依据 |

## 时效和有效性

- 每个数据源至少说明有效性何时置真、何时置假、超过多长时间过期。
- 上报与显示可以使用最近有效值，但必须根据过期标志提示，不能伪装实时。
- 传感器瞬断导致报警维持、静音或故障提示，需要按安全场景明确方案；不做泛化的无条件默认。

## 测试矩阵

每个重要功能至少有：编号、前置条件、步骤、预期值/状态、证据方式、当前状态。正常和异常同时覆盖：断传感器、断网/掉包、空数据、越限、用户按键、重启恢复、意外长阻塞。

“待执行预期”不得改写“已测试通过”。即使代码全部具备，也不能替代真实系统验证。脚本静态检查只能确定内容结构，不能保证电气或协议方案真的兼容。
