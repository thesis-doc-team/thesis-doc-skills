# 问题和整改建议逐条匹配规则（强制）

输入推荐使用结构化 `issue_pairs`：每个元素恰好包含 `problem` 和 `action`，可选 `verification`（仅作为写稿参考，不作为新表格栏目）。

1. 问题包含：明确模块/对象、具体需要解决/验证的事项、造成何种影响（若未实际发生则不要说“已发生”）。
2. 修改建议包含：如何修改、涉及哪个数据/接口/图纸/流程、如何自测/验证。
3. 输出时，先连续列出问题1…N，再列出建议1…N，**编号相同、数量相同、顺序相同**。
4. 每个编号独占 Word 段落，带首行缩进；标签“指导教师指出存在问题：”“指导教师提出修改意见：”也要独立段落，避免压成一行。
5. 禁止空泛句：“认真研究”“继续完善”“多查资料”“提高质量”；必须改成技术动作。
6. 若仅有技术规格、没有实际教师指导/错误证据，写“尚需检查”“建议验证”“需要补充”，不写成“教师现场发现”“某功能失败”。
7. 字数以行高和可用空间为边界；遇到多条问题优先保留高价值2~3组，而非挤爆表格；不缩改官方表格。

## 具体性三要素（强制，命中禁止项即返工重写）

每条问题和修改意见都必须具体到：

1. **对象**：实际的指令名、信号、参数、数值、数据字段、器件——`AT+CMGF=1`、CRC-8、火焰ADC阈值800、`state`字段、SIM900A、USART2，而不是"通信流程""相关参数"；
2. **动作**：对这个对象做什么（逐条执行/比较/修改/增加/标定/回放），**不能**只写"设计表格""整理资料""记录返回码""进行验证""开展测试""建立机制""核对流程"等元动作而不给内容；
3. **可观察结果**：看到什么算通过——收到`OK`/`+CMGS`应答、冷却期内仅1条短信、CRC错误次数为0、云端补齐数据无缺口、ADC读数随火焰靠近越过800。

**禁止清单**（出现在成品正文即视为意义不明）：

- **内部章节/附录引用**："按§5.5""对照§8.1""见附录11.4"——指导记录是独立文书，导师审阅时看不到你的技术文档目录，必须把被引用的内容展开成具体事实（阈值表→写出五个阈值数值；指令时序→写出 AT/ATE0/AT+CMGF=1/AT+CMGS 各步）；
- **无内容的元动作**："设计分步检查表""记录返回码""建立对照机制"后面没有具体对象和判据；
- **裸编号引用**：只写"（用例T07）"而不写独立可懂的动作描述；
- **套话**："认真研究""继续完善""多查资料""提高质量"。

**反例 → 正例（反例1为实际成品被用户点名退回的原句，整改后逐条示范）：**

| 反例（意义不明） | 正例（对象+动作+可观察结果） |
|---|---|
| 按§5.5指令时序设计分步检查表并记录返回码，分别模拟发送成功、无信号、模块无应答三种场景。 | 逐条执行 AT 握手、ATE0 关回显、AT+CMGF=1 切 Text 模式、AT+CMGS+Ctrl+Z 发送，记录每步实际返回（OK/ERROR/超时）；拔卡或屏蔽天线模拟无信号，确认重试 3 次仍失败后转本地蜂鸣并标记通信故障。 |
| 对照附录11.4整理阈值表并核对告警条件。 | 把粉尘 0.50 mg/m³ 越上限、温度 45.0℃ 越上限、湿度 20%RH 越下限、火焰 ADC 800 越上限、土壤湿度 30% 越下限逐项写入参数表，与阈值比较代码的比较符号和方向逐条核对一致。 |
| 用MQTT客户端订阅验证JSON合法与字段完整（用例T07）。 | 用 MQTTX 订阅 device/HY-001/data 主题，收到上报后校验 device_id、dust、temperature、humidity、flame_adc、flame_alarm、soil_moisture、state 八个字段齐全、类型正确，缺字段或解析失败即为不通过。 |
| 建立断线缓存机制并进行验证。 | 固件中增加断线重发队列：DTU 发送失败时把该条 JSON 暂存并按 30s 周期重试；拔线 5 分钟后恢复连接，核对云端该时段数据补齐、无缺口。 |
| 检查传感器采集并记录相关数据。 | 用干土/湿土两点实测土壤湿度 ADC 原始值，按线性映射标定 0—100% 的零点与满量程系数并把两点原始读数记入标定记录。 |

问题一侧同样适用：写清**哪个模块/哪条链路/哪个参数缺什么、影响什么**（对象+缺口+影响），不写"系统尚不完善""设计不够规范"。

**配对反例：** 问题1“通信模块上报失败”，修改意见1“界面字体调整” → 无关，必须FAIL。

**配对正例（匿名泛化）：** 问题1“串口数据帧缺少校验处理”；意见1“按协议校验帧头、长度及校验和，并记录异常帧日志进行验证”。
