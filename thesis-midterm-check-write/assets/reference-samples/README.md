# 内置去标识化参考范本（仅用于写法与格式）

## 四个范本及用途

| ID | 文件 | 可学习之处 | 不可照搬之处 |
|---|---|---|---|
| SAMPLE-A | `sample-a_environment-monitor.docx` | 完成进度按硬件/软件/论文层次展开；问题与整改分别列小标题 | 示例课题的功能、设备选型、完成结论；原整改段未严格编号，必须修正 |
| SAMPLE-B | `sample-b_data-platform.docx` | 多模块工作与下一步计划、问题与整改紧凑表达 | 多个问题挤在同一段及整改编号堆叠，这种方式在新版中是负例 |
| SAMPLE-C | `sample-c_facility-monitor.docx` | 问题条目独立分段、教师评语先肯定再建议 | 部分整改措施无一对一编号、篇幅是否满足官方要求须单独审查 |
| SAMPLE-D | `sample-d_mobile-inspection.docx` | 软硬件与论文进度综合总结、措施具有操作性 | 多条措施聚在一个长段、无验证方法，不能当作合格成品 |

## 已去标识化的信息

- 学生姓名、班级/具体年级、检查日期替换为示例标识。
- 特定项目正式标题替换为泛化的示例课题；部分独特的应用地名、业务词作了泛化，不把样本视为事实材料。
- Word 的 `docProps/core.xml` 与自定义属性中可能含有的作者/单位字段已清理或改为匿名标识。
- 原始模板中的栏目性质、段落层级及主要样式结构保留。去标识化后个别词长变化可能使样本页数发生自然变化，**不能据此修改官方模板分页**。
- 自动扫描所列姓名、届别、日期及原课题全称不残留；但常见技术名词（如 LoRa、GPS）属于通用技术，仍可能出现。禁止将其认定为用户当前课题事实。

## 运行规则

**文件来源边界：** 四个范本是**只读参考资产**，打包在 Skill 安装目录，永远不得写入当前项目 `project-assets/facts.json` 或 `references.json`；当前项目仍遵循“一项目一资产包”（`project-assets` 数据、`deliverables` 成品、`.skill-tmp` 运行区）。

**优先级：** 官方空白模板（结构） > 项目真实资料（内容） > Skill 的字数/分点/字体校验（成品质量） > 去标识化范本（表达与示例）。如在样本看到未编号的整改措施，只当负例；现行规则必须“问题（1）↔整改（1）”。

`sample-*.docx` 在本仓库中为只读文件，`samples-manifest.json` 记录内容摘要。更换/新增参考范本先匿名化、重跑扫描和逐页渲染，再更新清单；不得直接塞用户原始带姓名的毕业设计材料。

## 无法直接阅读 DOCX 时

先读 `references/anonymized-sample-text.md`（与本目录Word版本对应的文字镜像），再读 `references/sample-style-audit.json`（段落格式统计），无需联网也可以复用。需要确认视觉版式时再打开对应DOCX。
