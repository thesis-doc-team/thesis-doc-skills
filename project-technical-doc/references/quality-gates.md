# 输出文档质量门禁

## 1. 来源真实性（硬性）
- [ ] 没有复制范本中的设备、算法、指标、流程、表结构或应用场景充当新项目事实。
- [ ] 每个重要功能、参数和接口都能追溯到本次项目资料。
- [ ] 对资料陈述/架构设计/已写代码/真实测试做了区分。
- [ ] 未证实的模块、测试成功率、性能指标、完工状态没有写成已实现。
- [ ] 未使用行业通用知识偷偷补齐未知资料；不额外写未经项目确认的设计方案。

## 2. 交叉一致性（硬性）
- [ ] 主要功能在模块章节和流程章节能找到对应实现或明确待确认。
- [ ] 架构的模块连接与接口/通信描述一致。
- [ ] JSON、数据结构、表定义字段名及字段映射一致。
- [ ] 阈值方向、范围、示例数据、单位和异常行为不冲突。
- [ ] 相同技术能力在功能、架构、流程与测试各章中的实现状态没有互斥描述。
- [ ] 测试预期与实测结论分别呈现。

## 3. 文档可读性（重要）
- [ ] 有实际项目名称、项目概述、功能介绍、架构、核心技术、模块、流程和测试信息。
- [ ] 大章节有合理编号和目录，代码块闭合，图表均与文字对应。
- [ ] 模块至少解释职责、处理方式、依赖和失败边界中的关键项。
- [ ] 图表不是摆设，不存在凭空补造的分支和模块。
- [ ] 文中无残留【项目名称】/【填写】等占位语。

## 4. 项目安全与产物安全（硬性）
- [ ] 主技术文档没有“已知问题与改进建议”或等价的“存在的问题/改进方向/优化建议/风险与对策/未来展望/后续规划”等独立章节和尾部建议段落。
- [ ] 目录和所有 H2/H3 标题均已执行正文边界检查；附录已按新的章节编号重新连续编号。
- [ ] 来源里的待开发计划与改进建议只用于识别当前实施状态，未被挪入主技术文档。

- [ ] 源代码、项目资料、配置、测试数据等未被擅自改写。
- [ ] 不输出密钥、Token、密码、私钥和个人敏感数据。
- [ ] 未擅自执行联网、外设控制、刷写、数据库修改和破坏性测试。
- [ ] 生成文件位置清楚，覆盖文件需用户授权。

## 5. 结果等级与处置
- **PASS**：结构检查无错误，事实描述有来源支持，未出现越界章节。
- **WARN**：证据不足或存在局部矛盾，但已在正文标注、没有冒充事实；清楚向用户汇报待确认项。
- **FAIL**：缺乏任何实际项目依据而生成假技术正文、暴露秘密、重大事实互相矛盾且未披露、语法错误致文档无法使用。

脚本只校验部分 Markdown 结构。事实性、工程正确性和 Mermaid 可渲染性仍要按原资料复核。最终验收由用户负责。

## 6. HTML 用户展示门禁（V4 新增）

- [ ] HTML 由 **本轮输出的 MD 文件**生成，未并行从源码自行重写第二套正文。
- [ ] 全部保留章节与小节在导航和正文中同序出现；页面原文表格/代码/参数/流程完整，自动对照检查 PASS。
- [ ] Hero、能力卡、参数卡、过程卡从 MD 提取；缺少证据用“阅读路径/文档统计”降级，不借用示例项目内容。
- [ ] HTML 首页、导航、正文、页脚无越界独立章节或改善/未来规划板块；必要的真实状态、未验证信息仍保留。
- [ ] 流程图中 SVG/代码回退数量与 MD 对应；没有图形化的流程图在汇报中如实标记 WARN。
- [ ] **渲染内容断言全过（`validate_html.py` 自动执行，失败 = FAIL 阻断交付）**：每幅 SVG 的 `<style>`/`url(#…)` 引用闭合命中本图 id（防 id 前缀化后样式失配出黑块）、Mermaid 源标签 100% 存活于 SVG 文本（防标签被净化剥掉）、估算最小字号 ≥9px（否则 WARN）；模板 CSS 不得含未作用域的 `svg/path/rect/foreignObject/div/span/p` 元素选择器。
- [ ] **图区全局显示**：流程图完整呈现——容器无内层滚动条、无 `max-height` 压缩、无 `min-width` 溢出（CSS lint 自动拦截）；浏览器实测 `screenshot_audit.py renderprobe` 的 `container_scroll` 必须为 false、`height_ratio` ≥ 0.9、节点填充非默认黑且标签文字与节点底色有对比。
- [ ] 完整 HTML 无依赖远程 CDN 的 CSS、JS、字体、图像；可以单文件离线打开。
- [ ] 章节搜索、回顶、展开、移动抽屉、滚动进度能操作；页面在 1440px/768px/390px 宽度下无大面积横向溢出或重叠。
- [ ] **图示硬性**：MD 含至少 1 幅 Mermaid 图，「系统总体架构」「关键流程」章各有图（`check_markdown.py` 硬门禁，缺图 ERROR 阻断 HTML 阶段）；HTML 中 SVG/源码图数量与 MD 一致，HTML 0 图 = FAIL。
- [ ] **截图验证分析**：1440/768/390 三宽度截图逐张分析结论已记录（截图张数=实看张数、问题清单；截图先经字节级查重，相同哈希=拍摄失败重拍；截图集过覆盖矩阵 `screenshot_audit.py coverage`——1440/768/390 × 首页/含图章节/交互态 9 格齐全且字节互异，缺格或重复 = 拍摄失败重拍）；溢出/错位判定先经量测探针（`screenshot_audit.py probe`）再定性；浏览器不可用时明确记录“未执行截图验证分析”，不得谎称通过。
- [ ] **校验证据已留存**：同名 `<html>.audit.json` 已生成（publish/validate 默认输出）；HTML 派生页的 record-use 登记以此为凭证，无证据不得登记。
- [ ] 自动检查、浏览器检查、项目功能实测、用户验收是**不同概念**，分别汇报，不互相代替。

**优先级**：事实真实与内容边界 ＞ 双产物内容一致 ＞ 图表与交互完整 ＞ 视觉装饰。任何页面卡片都不能使未经验证的功能显得已经实测成功。

## 固定伴随产物门禁（v5.3）

- [ ] `physical-modules.json` 与 MD 同级、定名不加版本号；`gen_physical_modules.py` 生成；`check_physical_modules.py` PASS/WARN；只含实物模块，软件抽象层/纯逻辑/主程序不得列入。
- [ ] `content-index.json` 与 MD 同级、定名不加版本号；`classify_content.py` 生成；`check_content_index` PASS。
- [ ] 分类索引覆盖 MD 中全部表格、Mermaid 图与实物模块；缺项/多项即 FAIL。
- [ ] 每个 item 有稳定 `id`、`kind`、`category`、`group_id`、`group_title`、`line_start`/`line_end`、`content_sha256`；items 按正文行号排序。
- [ ] 每个 group 的 `item_ids` 与 item 的 `group_id` 一致，`count` 等于 `item_ids` 数量；相似项只做分组，不合并/删除原文数据。
- [ ] 网站展示由用户/下游处理；本 Skill 只交分类 JSON，不改 HTML 分组 UI。
