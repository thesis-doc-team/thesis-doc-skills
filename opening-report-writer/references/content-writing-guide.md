# 从技术文档逆向形成“开题报告”的写作规则

## 一、写作任务不是复制技术说明

技术文档说明“是什么、怎样实现”；开题报告必须说明“**为什么值得做、已有研究达到什么程度、准备研究什么、为什么可行、难点如何解决、在什么条件下按何计划完成**”。

转换关系：

| 技术文档源信息 | 开题报告使用位置 | 转写原则 |
|---|---|---|
| 系统定位、用户场景 | 1.1 课题背景 | 提炼实际需求和现有方式不足；不得虚构市场规模 |
| 功能及价值 | 1.2 研究目的和意义、3 任务要求 | 从“功能清单”转为可验收的研究任务与具体价值 |
| 学术/产业相关技术 | 2 国内外研究现状 | **新增外部真实文献核验**，不能把项目 README 当作国内外研究 |
| 架构、模块和数据流程 | 3 可行性、4 关键问题、6 方案 | 解释为何选用、怎样衔接，而不是复制大段接口实现细节 |
| 关键算法、通信机制 | 4 重点问题与解决思路 | “问题场景 → 技术方法 → 验证方式”，突出难点 |
| 工具、硬件、部署环境 | 5 工作条件 | 区分已具备、需要补充、可替代条件 |
| 开发与测试方案 | 6 方案与进度 | 整理任务序列、检查节点、指标验证方法，不捏造实测 |
| 附录、参考阅读、官方手册 | 7 参考文献 | 实际核验并对应引用；项目资料不等于公开发表论文 |

## 二、默认七章内容深度

### 1 课题研究立项依据

**1.1 课题背景**：从研究领域背景、典型使用对象与现有不足切入，逐步收束到用户实际课题。若“现实痛点”仅是工程动机，写“可解决/拟改善”，不能写“已造成 XX 人受损”之类未经核实的结论。

**1.2 研究目的和意义**：分清“计划达成的具体功能”“技术研究价值”“工程教学/应用意义”。用可考核目标代替空泛形容词；目标值须来自用户资料或经合理标记为建议值并等待用户确认。

### 2 国内外研究现状及分析

可以分 `2.1 国内研究现状` 和 `2.2 国外研究现状`，也可以反过来，但同篇全文一致。至少覆盖主要技术路线、代表文献及各自适用范围，再明确本课题采取的角度或工程差异。**不捏造学者姓名、结论、学术对比、企业产品或出版年**。若无法获得足够真实论文，应在结果中标记未完成门禁，不写臆造内容。

### 3 课题任务要求及实现预期目标的可行性分析

任务写成可实现、可验证的子系统任务；可行性从开发平台、成熟技术、人员时间、现有软硬件与测试场景展开。已有代码/资料是可行性证据，但并不证明整套毕业设计已通过最终验收。

### 4 重点研究的问题及解决思路

选 2～5 个真问题。每个写清“问题 → 造成困难的原因 → 拟采用技术路线 → 怎么验证”。不要把“成本低、先进、稳定”当作证据；不需要额外加入“已知问题与改进建议”独立章节。

### 5 完成课题所需工作条件及解决办法

列出开发设备、操作系统、编程环境、必要的网络/传感器/测试设备与参考资料，以及缺少条件时的可行替代。**没有的硬件不能写已具备**；没有预算依据不能编采购金额。

### 6 工作方案及进度计划

包含总体技术路线、阶段任务/交付件、验证与论文提交计划。按周次使用 `第X周--第Y周：具体任务`；禁止 `～`。所有阶段按真实任务书时间组织；用户未给的时间段可暂列合理序列，标注待任务书核对。

### 7 主要参考文献

按正文首次引用顺序排序，条目不少于 10，编号单次出现，正文上标与其一一对应。优先学术论文、学位论文、标准与官方资料，博客仅作可核验的辅助资料。

## 三、事实用词控制

| 证据 | 合适用语 | 不合适用语 |
|---|---|---|
| 技术文档提及尚未完成 | 拟采用、计划设计、预期达到 | 已实现、已达到、经过大量实验 |
| 有源码且有调用链，但没运行 | 已有源码实现逻辑、具备初步开发基础 | 系统运行稳定、测试全部通过 |
| 有已有测试记录 | 在所给测试环境与版本中测得 | 普遍满足工业级要求 |
| 性能只给要求目标 | 以 XX 作为预期评价目标 | 性能已达到 XX |
| 文献仅检索到书目条目 | 该文献讨论了 XXX 主题（以可见摘要为界） | 作者证明 XX 性能优于 YY（未经核对） |

## 四、避免无效内容和模板污染

- 不把技术文档的全部函数和参数表复制到开题报告（会破坏论证体裁）。
- 不把样例技术文档的产品和系统名称带入新项目。
- 不自动增加网页可视化、HTML 技术档案、APP、云平台、AI 模型等未经当前技术资料支持的功能。
- 不因为学校要求 3000 字就堆砌无依据“国内外研究均已成熟”“市场规模迅猛增长”。
- 不让参考文献、图标题、周次和章节标题脱离正文孤立排在下一页。
- 若需要插图，应先确认官方书写区能承载而不破坏版式；本版脚本主支持**纯文字与列表、标题**，不能凭空将 Mermaid 文字作为图片加入。用户确需配图则在不改变模板前提下扩展工具并逐页验收。
