# 开题报告生成质量门禁（强制检查）

## G0 模板完整性（任何一项错即 FAIL）

- [ ] 内置官方 DOCX 与 SHA256 相符。
- [ ] 官方原件文件绝对未写入、未覆盖；输出为新副本。
- [ ] 官方模板页边距、A4 纵向、节信息、页眉页脚、页码不变。
- [ ] 官方封面字段标签、学校名称、填表说明文字完全不变。
- [ ] 正文表格仍是 2 行 1 列，边框与表格结构不变。
- [ ] 正文要求文字、学生签名日期、指导教师意见及签名日期完全不变。
- [ ] 格式不靠新建近似 Word 替代模板。

## G0.5 双参考源分离与脱敏范本质量（打包与起草强制）

- [ ] 官方**空白**模板来自 `assets/official-opening-report-template.docx`，SHA256 与 V2 原件一致；匿名**已填写**范本来自 `assets/reference-samples/`，二者独立，不能互换。
- [ ] 参考范本已脱敏（学生、学号、导师、时间及文档作者元数据），测试 `python scripts/check_reference_example.py` PASS。
- [ ] 用户的原始已填写个人范本文件不在安装 ZIP 中；仅打包脱敏版本。
- [ ] 写作步骤先阅读 `references/anonymized-sample-usage.md`；仅模仿段落组织与层次，不从匿名范本向本项目事实/文献/周计划资产库迁入内容。
- [ ] 匿名范本若与官方模板、当前技术文档或已核验文献冲突，始终服从上级资料；保留历史范本的弱参考地位。

## G1 内容/证据（硬性）

- [ ] 只用**当前课题的技术文档**作为项目技术事实来源。
- [ ] 项目具体功能、硬件、算法、技术机制、参数、流程与技术文档一致。
- [ ] “设计”“计划”“已有实现”“已实测”没有混淆。
- [ ] 不凭空添加功能或断言已经验证的性能结果。
- [ ] 七项必需研究内容齐全，不把项目说明书大量原文机械搬运。
- [ ] 正文汉字 ≥ 3000，不包括学校填表说明、封面及参考文献。

## G2 文献真实性（硬性）

- [ ] 每条文献都有当前任务的核查依据（可查 URL/DOI、准确书目）。
- [ ] 至少 10 篇，优先知网/万方/维普/正式论文网站/出版社/标准官方网站。
- [ ] 学术、官方文献不少于 7 篇；CSDN 等博客至多 2 篇。
- [ ] 所有作者、题名、年份、出版信息不是臆造。
- [ ] 文献在正文至少有相关用途；全文每处引用支持对应论点。
- [ ] 正文首次引用顺序与文末 `[1]`、`[2]`…一致；编号无重复、无缺项。
- [ ] 共享文献库（REF-xxx）已优先复用；新核实文献已入库或在汇报说明未入库原因。

## G3 Word 格式（硬性）

- [ ] 新增正文五号宋体，英文 Times New Roman，1.5 倍行距；**普通正文（含周计划）每段首行缩进420 twips**，`check_report.py` 必须逐段判定，缺失即 FAIL。
- [ ] **参考文献也使用 1.5 倍行距**。
- [ ] **参考文献段落显式左对齐（`w:jc=left`）+ **420 twips悬挂缩进****，不使用两端对齐；`check_report.py` 未报"左对齐"类错误。
- [ ] `[1]`、`[1-2]` 引文为真实 `w:vertAlign="superscript"`，不能用普通文字假冒。
- [ ] 文末 `"[12] [12]"` 等重复编号为零；无 Word 自动编号叠加。
- [ ] 第一部分小标题选用“1.1 课题背景”，除非当前学校更具体规则明确要求不同。
- [ ] 计划周数使用 `--`，不出现 `～`、`~` 等替代。
- [ ] 不修改导师评语、教师签字、学生签字和原始表格。

## G4 截图验证分析（渲染与内容视觉验收，人工必须完成）

- [ ] DOCX 能使用实际具备的 Word/WPS/LibreOffice 工具按页渲染（未使用 WPS 不得写 WPS 已通过）。
- [ ] **截图验证分析已完成**：每页均已逐张分析，不是只看头尾两页；实看张数=截图张数，逐张结论与问题清单已写入执行汇报。
- [ ] 无内容裁切、覆盖、乱码、错别字、异常字体、超宽 URL。
- [ ] 不出现单独位于一页末尾的一级/二级标题。
- [ ] 学生签名和日期、教师意见和教师签名没有异常分离成孤立页面。
- [ ] 参考文献顺序、段落行距和长条目跨页均可读。
- [ ] 参考文献行内无两端对齐拉伸的大空隙（行内异常大空格）；长 URL 换行后仍可读、无句号孤行。
- [ ] 未单纯为了消除分页缺陷而改变官方固定版式。
- [ ] **实质性分页门禁**：页数仅是参考、不设固定指标；未为凑/压页数增删事实、稀释或堆砌文字；孤页已消除，或如实报告待用户判断。

## G5 交付目录整洁与共享资产纪律（硬性）

- [ ] 过程文件统一写入本轮运行目录 `.skill-tmp/opening-report-writer/<run-id>/`，交付前已用 `cleanup` 整体删除。
- [ ] 成品交付在 `<PROJECT_ROOT>/deliverables/opening-report/`；本轮版本（-vN）**恰好 3 项**：开题报告 DOCX、执行汇报-vN.md、文献核验台账-vN.md。
- [ ] 历史版本（-v1…-vN-1）保留未删、未覆盖；重生成用递增版本号。
- [ ] 无检索脚本/核验日志（lit_* 等）、下载的文献 PDF、渲染 PNG/PDF、中间 JSON、临时依赖目录残留。
- [ ] 已执行 `record-use` 登记（成品路径、实际 REF-xxx、sha256），activity.jsonl 有本条记录。
- [ ] 未删除、未改写 project-assets/ 共享资产、用户原始资料、官方模板原件及其他 Skill 的运行目录。
- [ ] 执行汇报已记录"交付目录最终清单"并逐一核对。

## G6 结果分级和用户验收

- **PASS**：G0～G5 全部通过（含脱敏样本锁、正文缩进复检、逐页实际截图），引用来源已实际核查，用户可以进入最终审阅。
- **WARN**：存在资料缺失、文献摘要受限、个别难以消除的视觉分页或不可用的渲染工具；在执行汇报逐项列出，不说“已通过全部检查”。若文献不足 10 篇或模板改变，不能使用 WARN 规避 FAIL。
- **FAIL**：模板固定内容被改、文献伪造/数量不足、系统事实严重无据、正文缺章/不足 3000 字、结构检查失败。

**自动检查 ≠ 视觉审查 ≠ 学术真实性 ≠ 用户最终验收。** 执行汇报分别列出结果。
