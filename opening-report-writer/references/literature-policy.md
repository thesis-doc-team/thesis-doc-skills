# 参考文献真实来源与 Word 引文规则

## 1. 必须从真实文献来源查证

首选中文论文平台：中国知网（CNKI）、万方数据、维普、学校图书馆数据库以及具体期刊/高校学位论文仓储。国际首选 IEEE Xplore、ACM Digital Library、SpringerLink、ScienceDirect、期刊和出版社官方网站、DOI 解析所指向的原始文献页面。适当使用正式 RFC、国际/国家标准机构页面和相关技术组织官方文档，尤其是计算机/电子工程软件系统课题。

**CSDN 可以引用**，但主要用于辅证编程实现或工程实务。优先查找其文章是否有指向原始论文、官方文档的引用；能引用原始文献时用原始文献。CSDN、博客园、GitHub README、个人博客或技术论坛原则上合计不超过 2 项，不作为国内外学术研究现状的主要证据。论文数据库中的索引页可以帮助定位，但搜索结果列表不是原论文。

## 2. 文献查证步骤

1. 用课题核心关键词构建 2～5 组中英文查询；先找相关论文/综述，再补充该项目核心技术的标准和官方文档。
2. 逐篇打开权威可见页面，核对作者、原题、出版/发表年、出版社/会议/期刊、卷期和页码、DOI 或稳定链接（若存在）；不要从搜索结果片段猜测缺失字段。
3. 至少阅读能直接获取的摘要或官方说明，判断与正文论点的关系；当论文全文不可读时，不引用其不可验证的实验细节。
4. 建立 `来源 URL/DOI → 文中哪句话 → 完整参考文献格式` 三项映射。
5. 以**正文首次出现的顺序**编号，核对正文 `[n]` 均能回溯到第 n 项参考文献。
6. 在报告 JSON 的 `references[]` 中写入 `text`、`source_url`（或 `doi`）、`source_type`、`verified:true`。这里的 `verified:true` 仅由真正检索并核对后赋值，**不得仅为绕过验证器而设置**。

## 3. 引文格式规则

- 在正文草稿 JSON 的一段话中插入：`本研究拟综合现有方法[[cite:1-3]]，设计……`。
- 成品中呈现：`本研究拟综合现有方法` + **真正上标的** `[1-3]` + `，设计……`。
- 禁止在用户可见 Word 内保留 `[[cite:...]]` 或 `[n]` 的普通基线正文引文。
- 参考文献行直接生成 `[1] 作者. 题名[J]. 刊名, 年, 卷(期): 起止页码.`，条目中**不再写 `[1]`**，禁止 Word 自动列表重复编号。
- 正文和参考文献统一 1.5 倍行距。参考文献编号可以不加上标，正文引文必须上标。
- 不要把 DOI/URL 以裸链接孤立在下一页；长链接换行、悬挂缩进与文献段内分页均在渲染后检查。

## 4. 不能靠自动化脚本保证的事实

“文献存在”“论文确实支持该句话”“DOI 指向正确标题”“数据库搜索没漏掉论文”“某论文已被学界认可”**不能单靠 JSON 的 verified 字段判断**。该字段只是 Agent 手工核验记录，自动检查仅验证字段填写和布局。没有实际访问权的数据库不得假称已登录、已阅读付费全文；无法核实的条目从最终文献中剔除或标记待核查，不伪造。

## 5. 数量与类型

学校最低 10 篇。本 Skill 默认至少 7 篇来自期刊、会议、学位论文、专业书籍、正式标准、官方技术文档；技术博客最多 2 篇。以上来源类型比例是**质量建议及本 Skill 默认门禁**，不是学校官方文件另设的数量条款。如用户正式学院规定更严格的学术文献占比，以其为准；必要时可调整本 Skill 的检查规则，但须记录用户授权。
