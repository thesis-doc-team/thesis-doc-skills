# 用户需求归纳（可作为后续合并 Skill 的验收依据）

1. 根据当次技术文档编写毕业设计**指导记录**，不能误写成开题报告/任务书/中期检查记录。
2. 先逆向研究过去已填Word范本的共同结构、版面和写作方式；差异用官方模板优先、再证据/常识处理。
3. 官方空白表的框架绝对不能被改动：字体字号、页面属性、表格线/合并/行列、说明文字、固定标签、评价、签字栏等必须保留。
4. 空白表的页数只是参考；必须允许按实际内容扩展，A4打印不少于8次指导。
5. 指导内容结构固定为“存在问题—修改意见”，问题逐条编号，对应解决办法分点、一一匹配，不要套话。
6. 必须从真实技术资料提取信息，注重准确表达；不可继承其他范本人物/项目的技术事实，不伪造指导事实。
7. 参考论文优先学术网站/知网/万方/维普等，CSDN只作补充来源；已查证文献和周计划长期共用。
8. 一个项目一套资产包，明确 `数据/project-assets + 成品/deliverables + 运行区/.skill-tmp`，每个文书 Skill 可以合并协作。
9. 交付 Word、格式及内容检查汇报；中间文件清理但不能删除正式资料、共用资产或历史版本。
10. 将早期已填范本做去敏处理后放进 Skill 供长期复现，并为稳定性提供脚本与自测。
11. 作者/学生最终判断是否验收，AI负责执行与透明反馈，指导教师负责真实审核、勾选和签字。

**已知源模板固有冲突**：不改原始行高与“一次一页且不跨页”不可同时保证。默认不改学校固定框架，跨页纳入 QA 的 WARN 并解释给用户，而不是静默重排。
