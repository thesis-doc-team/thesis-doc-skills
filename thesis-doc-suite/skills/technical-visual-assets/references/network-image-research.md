# 联网实物图检索与审核规范 v1.0.0

## 目标认知
先从**真实技术 MD + FACT**确定目标：完整执行器/完整控制板/完整传感器模组/完整通信模组/仅芯片。搜图不是根据模糊关键词任意挑一张相似图片，必须保留对象层级、厂商型号、板卡变体与实际项目身份。五张用户正反例见 `image-selection-examples.md`，筛选前必须实际查看。

## 检索通道及降级

1. 优先现有 Claude Code 的 WebSearch、WebFetch、浏览器和已知厂商官网渠道（若已提供），带型号的官方产品页最高优先。
2. `scripts/search_candidates.py --provider auto`：**当前环境已有** `ddgs` 时尝试其图片搜索；其后用 Python 标准库匿名访问 Openverse / Wikimedia Commons 公开 API，返回图片 URL 和来源页（不保存任何图片）。如 API 不可访问或为空，就报告真实状态，不伪造。
3. 百度 / CSDN / Bing 等页面仅做发现线索。搜索结果可能返回空白、垃圾、缩略图、被反爬污染内容；必须回溯原始页面。没有可用浏览器不自动安装 Playwright、Selenium、Crawl4AI、imagedl 或执行 `npx`。
4. 不尝试验证码绕过、登录规避、绕开网站条款等行为。
5. 所有引擎失效也可以先在本地生成真实系统架构和功能图，不需要再运行技术文档生成器。

## 逐张图片实际审查

| 问题 | 合格标准 | 不合格处理 |
|---|---|---|
| 主体完整性 | 整块 PCB、整个执行器、完整模组或整机单元 | 裸芯片、引脚、局部电阻、配件/截断图：拒绝作 module-photo |
| 型号匹配 | 完整型号/厂家/版本与技术 MD/FACT 对应 | 只有系列号/相似型号：仅 reference-only 候选，不计覆盖 |
| 技术价值 | 足以让读者认出目标模块、接口和整体结构 | 水印、模糊、广告或无关背景：拒绝 |
| 原始来源 | 可回查产品页或作者发布页及原图 URL | 只有搜索摘要：不得标记来源已核验 |
| 复用许可 | 具体许可证、作者、署名与适用范围 | “官网有图”“百度能搜到”不等于可转载；保持待审 |

**审查“完整目标”时优先核对原产品页的同一具体型号和照片细节。** 文字审查记录和程序命令中 `--full-module-confirmed` 只是人工/模型声明，不能当作计算机视觉识别结果。不得伪造 `--source-checked-at`、`--permission-evidence` 或视觉观察文字。用户未允许下载时，只可保存元数据或在对话中展示已有搜索图片，不把图片文件下载到项目。

## 没有明确开发板型号怎么办？

例如 MD/FACT 只有 `STM32F103` 芯片系列；网上查到的是 `STM32F103C8T6 Blue Pill` 开发板。即使整板主体清晰，仍然不能把它批准为用户真实主控板。此时请：

1. 解释目前事实只有芯片系列，具体开发板或自制板尚未确认；
2. 将准确芯片的产品封装图与板卡示意图区分（芯片图不属于完整主控板 `module-photo`）；
3. 如用户愿意，提供“同类开发板参考图”线索，但不批准、不计覆盖；
4. 如上游已有图纸或实拍，可用事实审核机制建立精确板卡事实，之后再选图。

## 最小网络行为

仅在现有工具能力内做搜索和来源查验。没有图片保存授权，绝不运行下载脚本。对用户授权的单张选中图片也只通过安全 HTTPS 获取 PNG/JPEG/WEBP，不下载 PDF/ZIP/HTML/可执行文件，不能强行回避访问限制。使用了任何外部网络工具都要在最终执行汇报中如实列出。
