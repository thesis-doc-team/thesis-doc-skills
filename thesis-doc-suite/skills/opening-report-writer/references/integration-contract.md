# 与 project-technical-doc v5 Skill 的组合接口

## 组合目标

现有上游 Skill `project-technical-doc`：读取当前项目源码或技术资料，生成 **MD 技术文档 + 用户 HTML 展示页**。本 Skill `opening-report-writer`：只从当次项目技术文档中抽取开题论证所需的事实，独立查证公开参考文献并产出官方 Word 模板中的开题报告。

两者的**最小输入输出契约**：

```text
用户当前技术资料/源码（上游处理）
  └─ project-technical-doc → <项目名>-技术文档.md
                                 ↓（用户指定/明确传入）
                          opening-report-writer
                                 ├─ 读取事实台账、技术模块和研究边界
                                 ├─ 查找独立的学术参考文献
                                 ├─ 撰写开题报告七项内容
                                 └─ 官方模板复制填报并验证
                                 ↓
                  <项目名>-毕业设计开题报告.docx
                  执行汇报.md
```

## 共享内容、独立职责

| 项目 | 上游 Skill | 本 Skill |
|---|---|---|
| 技术事实 | 产生经整理的项目功能与架构 | 只消费，不重写事实 |
| 核心成品 | MD、HTML | 官方模板填报的 DOCX |
| 真实论文检索 | 非必须 | 必须；与项目技术事实来源分离 |
| 开题研究论证 | 不负责 | 独占负责 |
| HTML 技术可视化 | 负责 | 不允许产生 |
| Word 模板 | 不负责 | 只能使用用户正式官方空白模板 |
| 风险与当前缺口 | 已有事实边界可使用 | 仅转成开题报告“拟解决问题/可行性”，不可虚构未验证结论 |
| 终审 | 用户 | 用户 |

## 合并时避免的三个冲突

1. **文体冲突**：技术档案客观描述已有系统；开题报告讲研究动机和准备实施的任务。不能将技术档案十章直接复制到七项开题报告。
2. **证据冲突**：项目资料可证明“本项目的设计或实现”，但不能证明“国内外学术界发展现状”。学术文献必须单独真实检索。
3. **格式冲突**：上游的 Markdown/HTML 风格不能覆盖学校官方 Word 模板；本 Skill 的 DOCX 是独立的模板限定结果。

## 最佳调用方式

- **单独使用本 Skill**：用户直接上传本项目技术文档和开题报告需求，运行本 Skill。
- **联动使用**：先运行上游生成 MD，经用户允许后将其作为本次输入，再启动本 Skill。
- **以后合并成父工作流**：由一个调度器调用两个子 Skill，按“技术文档确认 → 开题报告编写”顺序执行，保留两个子 Skill 的不同验收与输出范围；不要把上游的网页输出步骤挪入本 Skill。
