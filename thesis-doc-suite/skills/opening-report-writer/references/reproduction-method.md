# 逆向复现方法：从给定 Word 范本到可审查的开题报告

## 四层复现模型

**第一层，外壳（官方二进制模板）**：源 DOCX 的 ZIP/OOXML 作为唯一合法排版来源，不做全新排版。记录 SHA256 和固定内容清单。生成 DOCX 时只允许触及指定的书写槽位。

**第二层，内容论证（技术文档的项目事实）**：根据本次技术文档形成“课题范围/功能/方案/资源/已有证据”矩阵，再重新组织为七项开题研究任务；不是一键改写技术文档的章节名称。

**第三层，外部学术证据**：对研究背景、国内外现状和技术方案选择所需论点单独查证真实论文与标准；每项文献与正文句子存在一对一支持关系。不能把已有技术说明、搜索结果片段当作学术研究现状的全部证据。

**第四层，双验证**：机器负责验 `.docx` 固定结构、字体、上标、行距、编号和字数；图像渲染负责检验视觉效果、分页和签字区是否孤立。两者未通过时不得结束。

## 具体的逆向操作顺序

1. 原件作为只读资产入库，并保存 `SHA256`。
2. 解包只读检查 `word/document.xml`、`word/styles.xml`、`word/numbering.xml`、`word/_rels`、页面节属性、表格边界、段落与运行属性。
3. 逐个标记 **静态固定区 / 可填字段 / 连续正文书写区 / 签名受保护区**；与用户核对有实质争议的边界。
4. 确认学校的**正式文字约束**与“参考范本中经常出现的写法”两种层级，不把惯例说成学校硬性规定。
5. 采用固定七章预设，针对当前技术文档写新的研究内容；真实学术文献支持外部现状。
6. 对引文采用特殊标记（`[[cite:n]]`），最终转成 Word `w:vertAlign superscript`，不使用 Unicode 上标模仿。
7. 用 OOXML 把正文插入第一行表格的留白区，在不改变注释、签字区、表格和节属性前提下调整占位空行。
8. 从原模板与输出文档逐部件比对 ZIP 成员、受保护的 XML 元素与段落文本；发现非授权改动就失败。
9. 导出成页图和 PDF 进行目视检查，调整**新写入正文**（不得擅自改变官方模板）以解决孤立标题/签字、溢出等视觉缺陷。
10. 在执行汇报里列出真正验证的事实、文献、排版结果，最后由用户审核。

## 不可混淆的边界

- “模板原件完全不变”与“填写后副本的正文区域发生变化”可以同时成立；否则无法把开题报告内容写进去。
- “格式机械通过”不代表“内容合适、文献真实”或“分页看上去完美”。
- “学校要求包含七项研究内容”不等于“学校已规定七个具体一级标题文字”。
- “CSDN 可被引用”不意味着它能代替知网期刊、硕博士论文或标准原文；来源选择需与所证明的论点适配。
