# 毕业设计任务书输出质量门禁

## 0. 优先级

**官方模板原框架不变与技术真实性 ＞ 参考文献真实性 ＞ 内容完整与工作进度合理 ＞ 格式视觉效果 ＞ 页面数和装饰。** 用户实际审查是最终门槛。

## 1. 输入与范围

- [ ] 本轮明确指定的是**任务书**，没有误生成开题报告、技术报告、论文、HTML 网站等。
- [ ] 技术内容只取自当前用户本次指定的项目资料/上游技术文档。
- [ ] 已填范本只提供写法，不在新任务中保留旧课题、旧人员、旧时间、旧文献等。
- [ ] 有来源不足、已实现与待完成冲突时，未擅自把推断写成事实。

## 2. 模板不可变项（结构校验必须 PASS）

- [ ] 官方模板原件不被覆盖，生成路径不同；检查原件 SHA-256 不变。
- [ ] 页面宽高、页边距、节数、原始主表数量不变。
- [ ] 表格 `tblPr/tblGrid`、行 `trPr`、单元格 `tcPr` 不变；行列与合并关系不变。
- [ ] 官方标题、栏目名称、正文标签、表格外 4 条附注不改字/不删。
- [ ] 官方签名、签署日期栏完整且未冒签、未虚构签署时间。
- [ ] **允许**在可填写区域内生成正文段落，并允许合法的自然跨页，**不能**以官方空白模板 3 页为填充后必须 3 页的指标。（**自然分页原则**：页数无上限；只要没有溢出、整页异常空白、孤立签名或格式损坏，就不因页数多少而判失败。不得为凑/压页数增删事实或改版式。）

## 3. 任务书语言与覆盖度（事实人工审查）

- [ ] 设计目标、项目应用场景、主要功能、关键技术与集成/测试任务有对应证据。
- [ ] 不借用其他课题的技术内容；不为凑字数填充虚词。
- [ ] 不为省页数删减核心功能或工作阶段。
- [ ] 进度周次完整覆盖 `[1..N]`、无缺周/重周；没有把“计划完成”写成“已证明成功”。
- [ ] 任务下达人意见不少于 50 字且内容有针对性，标明为导师待审拟稿；五要素齐全（主体选题/能力/文书质量/针对性/收束语"最终评价以指导教师审定为准"），未代签、未写签署日期。

## 4. 参考文献硬门槛

- [ ] 至少 10 条真实可定位文献，整体与本项目相关；没有仅为了达标凑条数。
- [ ] 每条有 `source_url`、类型和实际核验记录；可检查作者、题目、刊名/学位单位、年份及必要出版详情。
- [ ] 正式论文、技术资料/CSDN 网页明确区分，网页资料没有伪装成期刊论文。
- [ ] 不重复记同一篇论文，不伪造 DOI/页码/卷期/年份。
- [ ] 如访问受限，则区分“核验了公开书目”与“读了全文”；未验证的内容如实说明。

## 5. Word/WPS 适配与截图验证分析（必须人工逐张看）

- [ ] 首页学院、班级、姓名、学号、题目、起止时间、导师、职称的**实际可见单元格**均水平/垂直居中。
- [ ] 内容不是用多个空格、tab、超大缩进或多余空段“假居中”。
- [ ] 中文正文五号宋体、1.5 倍行距；英文及罗马字符 Times New Roman 正体；模板标签原样保留。
- [ ] **截图验证分析已完成**：逐页渲染 PNG 并**逐张分析**（重叠/截断、边框错位、溢出、标题孤立、签名覆盖、异常空白页、字体替代），实看张数=截图张数，逐张结论与问题清单已写入执行汇报。
- [ ] 若 WPS 未实测，则明确写“尚未在 WPS 实测”，不能以 LO 渲染正常替代 WPS 验收。

## 6. 共享资产与清理检查（新增）

- [ ] 项目根目录与 project_id 明确，未误读其他项目的参考文献或周计划。
- [ ] 读取旧的 `project-assets/references.json` 和 `schedule.json` 后才决定是否需要检索与重新排程；已核验相关论文能够通过稳定 ID 复用。
- [ ] 新引文、事实或计划更改已写入固定项目资产目录，核验信息、状态、变更原因和调用方可回查。
- [ ] 所有文书局部 `[n]` 编号都由实际选中的稳定文献 ID 导出；未在项目共享库中重复保存大批文书专用引用文本。
- [ ] 使用的共同周计划与本轮学校时间要求一致；`draft` 未假称 `confirmed`，没有暗中覆盖历史计划。
- [ ] 临时 JSON / PNG / PDF / DOCX / 调试缓存都位于本轮带标记目录，成功/失败后**安全删除**；用户资料、模板原件、共享项目资产、最终 DOCX 和必要执行报告均未误删。
- [ ] 真实完成的最终 DOCX 与引用 ID 已记录到共享资产活动日志；失败的生成未伪称已交付。

## 7. 状态与处置

- **PASS（可交付供用户审查）**：结构比较 PASS、内容事实审核合格、≥10 已验证参考文献、字数/周次合格、逐页渲染无异常，清楚披露 WPS 检查范围。
- **WARN（需显式披露）**：不影响本版主体的个人信息缺失、用户尚未给出院校日期、尚无法实际 WPS 检查、某些文献只核验公开元数据等；允许交付待用户补填/确认的草稿，禁止标为最终学校审核通过。
- **FAIL（不得称合格）**：模板结构被重建/损坏、主要技术内容虚构、参考文献不足 10 条且伪称达标、技术任务严重缺失、签名伪造、布局明显截断或不符合官方规定。

脚本 `scripts/validate_taskbook.py` 仅核查能自动证明的部分：官方固定 XML 框架、字数、引用条数、编号、字段居中属性。**无法自动证明文献确实存在、内容绝对正确或 WPS 视觉一致**。执行报告必须写明这些检查是否真正执行。
