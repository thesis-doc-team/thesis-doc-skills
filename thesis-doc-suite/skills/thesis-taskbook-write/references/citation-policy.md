# 参考文献来源、核验与引用制度（专用于任务书）

## 必须区分 3 种东西

1. **学术检索入口/数据库**：帮助确认一篇文献是否真实存在，并取得作者、题名、期刊/学位机构、出版年份及可能的 DOI 等。
2. **可引用的独立文献本体**：期刊论文 `[J]`、学位论文 `[D]`、会议论文 `[C]`、学术专著 `[M]`、标准 `[S]` 等。
3. **技术性网络资料**：官方手册、开发者博客/CSDN、开源项目文档、技术问答等，通常要按其真实来源类型标识 `[EB/OL]` 或适合的电子文献格式；**检索网站不是论文作者，CSDN 博文不是自动变成期刊论文**。

模板写明“主要参考文献：（不少于10篇）”。优先从第 2 类取得至少 10 条与**当前项目**密切相关的、已核验的正式学术文献。CSDN 可以按用户要求作为**辅助引用**，特别用于操作系统接口、协议用法或工程实践的技术背景；但应有作者/标题/日期/原文 URL 和可信的技术内容，不能以大量不明来源的转载代替论文。学校另有文献种类要求时，以最新学校规定为准。

## 来源优先级和入口示例

| 优先级 | 来源 | 适用信息 | 原则 |
|---|---|---|---|
| 1 | 中国知网 CNKI https://www.cnki.net/ | 中文期刊、硕博论文等 | 在具体记录页核实元数据，必要时用校园授权访问 |
| 1 | 万方数据 https://www.wanfangdata.com.cn/ | 学术期刊、学位论文、会议论文 | 检索原文或可靠元数据记录，注意同名重名文献 |
| 1 | 维普 https://www.cqvip.com/ | 学术期刊 | 交叉核实收录期刊与论文信息 |
| 1 | IEEE Xplore https://ieeexplore.ieee.org/ | 电子信息、通信、嵌入式技术会议及期刊 | 优先出版方元数据、DOI |
| 1 | ACM Digital Library https://dl.acm.org/ | 计算机科学论文 | 核验作者、出版会议/期刊、DOI |
| 1 | 高校机构学位论文库/出版社/期刊官网 | 学位、图书、学术论文 | 直接确认正式记录 |
| 2 | DOI https://doi.org/ / Crossref https://search.crossref.org/ | DOI 和出版元数据核验 | 适合二次核验，不能只凭搜索引擎片段 |
| 2 | 中国大学 MOOC/官方手册或 Linux man-pages https://man7.org/ | 技术接口解释 | 作为技术支撑，不伪装成正式论文 |
| 3 | CSDN https://www.csdn.net/、其他技术博客 | 具体实现方法、经验性分析 | 标识来源性质并核查内容；不能冒充学术论文 |

**注意**：搜索结果片段、二手转载、AI 自动生成的“参考文献清单”不能代替可追溯的原始记录。若数据库需要登录而本地不可访问，可通过出版商记录页/DOI/学校图书馆书目、用户提供的文献资料等交叉核对；仍无法核验的必须标记“待核验”。

## 跨文书共享与复用（新增门禁）

- 实际检索前先读取当前项目根目录 `project-assets/references.json`，已核验且相关的引用不要求每次重检索、重录入；通过 `REF-xxx` 稳定 ID 取用。
- 本文书的 `[1]...[N]` 是**局部展示编号**，不写入长期文献 ID；开题报告可以引用同一篇论文但采用另一组局部编号。
- 新检索的文献先进入同一项目共享库，记录实际链接、核验日期、元数据与项目适用说明，避免后续 Skill 再造一份矛盾记录。
- 共享库“verified=true”不免除**本次相关性**和**有效性**判断。数据库书目信息变动、元数据缺失、网页消失或学校新规定时，补充查证后有理由地更新，并保留变更记录。引用不足时继续检索，不伪造。
- 共享库之外不要创建“任务书单独的永久参考文献副本”；`taskbook-input.json` 是中间组合文件，生成后清理。

## 检索工作法

1. 从本次技术资料抽取 3～8 个主题关键词簇，分别覆盖“研究目标、系统/算法方法、底层技术、测试/应用领域”。
2. 使用主题词 + 近义词检索 CNKI/万方/维普等；选与系统实际技术路径紧密相关的论文，不为了凑 10 条塞不相干论文。
3. 逐条打开可追溯页面，记录文献来源链接，核对**题名、作者、出版年、期刊/出版社/授予单位、卷期/页码/DOI（如存在）**。
4. 去重（同一文献被不同网站或不同格式收录不能算作两篇）；检查研究方向覆盖，不重复堆砌无关文章。
5. 记录 `verified=true` **仅当已实际核对**。脚本只能检查“是否存在核验字段”，**不能代替真人/Agent 打开原始来源的真实性核验**。
6. 按官方模板原位置填充 `[1]` ～ `[N]` 连续编号；正文实际引用的类型及著录信息应一致，书写格式优先遵守学校要求（通用可参考 GB/T 7714）。

## 一条真实引用的最小核验记录

```json
{
  "citation": "作者. 论文题名[J]. 期刊名, 出版年, 卷(期): 页码.",
  "source_url": "https://实际能定位到这一篇文献的页面",
  "source_type": "journal",
  "verified": true,
  "checked_at": "实际核验的日期"
}
```

上面只是**字段示意，不是真实论文，绝不能当作任务书中的一条参考文献**。若没有确认完整卷期或页码，不要编造；可先追查其他权威来源，仍缺失则在报告说明并标注待核验。

## 不可触碰的红线

- 没有实际打开证据页却勾选 `verified=true`。
- 将不存在的 DOI、页码或刊名“补全”得看起来完整。
- 无出处地把 CSDN 文章写为 `[J]`；把 GitHub 仓库写成会议论文。
- 从以前的农业、井盖、矿井、机器人等任务书中直接复制参考文献，而不是依据新项目筛选。
- 因为正式学术文献不足 10 篇便自动捏造剩余条目；此时应继续检索或交付**明确未完成的草稿**。

## 关于数据权限

有些数据库全文需校园网、机构账号或购买权限。允许依据可追溯的可靠书目元数据完成**书目信息核验**；但不得宣称“读完全文”，除非确实取得并阅读了全文。尊重版权，不批量绕过付费或复制受限论文全文。
