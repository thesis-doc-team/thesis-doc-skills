# 供其他文书 Skill 直接复用的共享资产规则片段

> 本文件是可以复制到**另一份** Skill 中的框架建议。复制前确认该 Skill 的文书边界、自己的模板、输出路径与章节名称；**不表示本任务书 Skill 会自动替用户修改别的 Skill**。

## 建议加入新 Skill 的共同约束

```markdown
## 项目级共享资产：强制先读后写

- 当前项目根目录固定使用 `<PROJECT_ROOT>/project-assets/`；同一项目必须使用一致的 `project_id`。不得将不同项目混用。
- 首先读取：`project.json`（项目身份）、`facts.json`（技术事实和来源）、`references.json`（可复用文献）、`schedule.json`（项目级周计划）、`activity.jsonl`（变更与使用记录）。目录不存在时初始化，已存在不得重建覆盖。
- 参考文献沿用共享库的 `REF-xxx` 稳定 ID 和核验元数据；本份文书另行挑选适用文献并生成自己的 `[1]...[N]` 引用序号。不可因引用存在而省去文献真实性与相关性复查；新查证论文应更新共享库。
- 周计划沿用项目级基线的周次和实际内容；不同文书可以适当改变措辞详略，不得无依据改日期、总周数或阶段。`draft` 不得自称 `confirmed`；要修改基线，明确原因并同步记录。
- 技术事实复用 `FACT-xxx` 与原始来源；新 Skill 的“拟开展任务”写作口吻不改变共享事实的证据状态。
- 现有资产有冲突时，不得静默覆盖；将证据和变更原因记录在共享活动日志。必要时征求用户决定。
- 每份文书的页面结构、官方模板和验收规则仍由该 Skill 自己负责，项目资产库只提供事实/引用/计划，不决定版式。
- 所有中间文件仅放本 Skill 自有的运行临时目录并加所有权标记；成功和失败都清理本轮中间文件。不得删除用户原始资料、官方模板、project-assets/、最终交付文件或其他 Skill 的临时目录。
```

## 接入方式

1. 在其他 Skill 的输入阶段加入“识别 PROJECT_ROOT/project_id → 读取已有资产”。
2. 在事实与参考文献检索阶段，把“优先复用已存在 ID”放在检索之前；把“核验新文献并登记到共享库”放在写文书之前。
3. 在任务规划阶段，先读 `schedule.json`，只在正式需求与已存计划不一致时提出项目级更新。
4. 在文书完成阶段，按自己的模板输出最终 DOCX 或其他格式，并记录真实使用的文献 ID。
5. 增加自己的 `.skill-tmp/<skill-name>/<run-id>` 安全清理实现，不可直接用任务书 Skill 的 `cleanup` 删除其他 Skill 的目录。

协议源文件：`references/shared-project-assets-contract.md`。可复用数据管理命令：`scripts/project_assets.py`；其他 Skill 可以直接调用这些**资产管理**命令，或自行实现相同 JSON 格式，但**不应调用 `fill_taskbook.py` 来生成开题报告**。
