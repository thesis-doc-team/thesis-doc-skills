# 图表几何/视觉门禁（diagram-visual-qc）

## 1. 四类真实失败样本

用户实际使用中出现过以下失败图：

| 失败 | 表现 | 根因 |
|---|---|---|
| 超长横向图 | 架构树宽到超出 A4，插入 Word 后字小到看不清 | 只按容器 `max-width:100%` 缩放，没有检查适配后的字号 |
| 断线 | 节点之间连线断开、箭头悬空 | 边的端点没有落在节点包围盒附近；marker 引用失效 |
| 截断 | 图上下/左右被裁，线条不连续 | 图过高/过宽 + 容器裁切；没有几何门禁 |
| 文字重叠 | 分层架构图里汉字叠在一起、拥挤不可读 | 自动布局未考虑 CJK 宽度；节点/文字包围盒相交 |

## 2. 门禁规则（`scripts/diagram_qc.py`）

对每张渲染后的 SVG：

| 检查 | 阈值 | 级别 |
|---|---|---|
| 宽高比过大 | `aspect > 10` | FAIL |
| 偏宽 | `6 < aspect <= 10` | WARN，建议改 TD/拆图 |
| 过高 | `aspect < 1/10` | FAIL |
| 适配正文宽 1080px 后最小字号 | `< 9px` | FAIL |
| 节点包围盒重叠 | 交叠 > 较小节点面积 18% | FAIL |
| 文字包围盒重叠（CJK 宽度估算） | 交叠 > 较小文字面积 18% | FAIL |
| 连线端点未接到节点 | 距最近节点 > 18px | FAIL |
| marker 引用不存在 | `url(#id)` 找不到 | FAIL |

**节点数量不是错误**：系统架构图 50–80 个节点可能完全正常。门禁不按节点数判失败，也不建议为了“过密”删节点；只有在字号、重叠、断线、宽高比不达标时才要求重排/拆图。信息完整性优先。

## 3. 自动排版修复（`scripts/diagram_svg.py`）

渲染后立即 QC；FAIL 时按顺序尝试：

1. `LR/RL` 横向图 → 改为 `TD` + 加大 `nodeSpacing` / `rankSpacing` / `padding`；
2. `TD` 图 → 直接加大节点/层间距重渲染；
3. 仍 FAIL 且有 Graphviz `dot` → 用 Graphviz 回退重排；
4. 仍 FAIL → 发布 BLOCK，要求人工拆图/改布局。

**不删除节点、不改技术语义**；只改方向、间距、渲染器。

## 4. 接入位置

- `diagram_svg.render_diagrams()`：渲染后 QC + 自动重试，报告写入 `geometry_qc`。
- `validate_html.py`：对 HTML 内每张 SVG 再跑 QC；FAIL 计入 errors，阻止 PASS。
- `publish.py`：`geometry_qc` FAIL 直接计入发布 errors。
- `tests/test_diagram_visual_qc.py`：过宽、偏宽 WARN、断线、文字重叠、节点重叠、60 节点但可读、正常图共 7 项回归。

## 5. 边界

- 这是机械几何检查，不能证明流程语义正确，也不能替代 Word/WPS/浏览器逐页目检。
- CJK 文字宽度按 1em 估算，实际字体度量会有差异；门禁偏保守。
- 自动重试只改布局，不改技术事实；如果原 Mermaid 本身节点/连线错误，必须回到技术 MD 修订。
- 节点多不是失败；拆图是最后手段，且拆图后仍要保留全部信息与来源。
