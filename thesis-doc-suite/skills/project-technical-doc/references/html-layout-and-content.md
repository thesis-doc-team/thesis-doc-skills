# V2 风格复用：布局、组件与内容转换规范

> 此规范从用户确认的 V2 可视化 HTML 中提取**版式与交互**，只固化“范本”，不固化原范例项目内容。配合 `assets/layout.html` 使用；其中 CSS、DOM 层级和内联 JS 已保留对应设计。

## 一、页面结构（从外到内）

```text
body
├─ #progress                        4px 顶部阅读进度
├─ .mobile-header                   手机顶部标题+菜单
├─ #sidebar-scrim                  手机抽屉遮罩
├─ aside.sidebar                    左侧固定导航
│  ├─ .brand                        通用项目标识（卡通机器人图标）
│  ├─ .nav-scroller
│  │  ├─ .sidebar-search             章节全文匹配搜索
│  │  └─ nav#site-nav
│  │     ├─ .nav-overview            展示总览
│  │     └─ .nav-chapter × N        章节链接 + .subnav × M
│  └─ .sidebar-bottom               版本与范围说明
└─ main.page
   └─ .page-inner
      ├─ .top-bar                    面包屑/静态页面标签/章节数
      ├─ section#overview
      │  ├─ .hero                    项目介绍 + 抽象科技插画
      │  ├─ .status-notice           有必要的真实性/范围说明
      │  ├─ .feature-grid            核心功能或主要章节卡片
      │  ├─ .overview-grid
      │  │  ├─ .overview-card         工作步骤/阅读路径
      │  │  └─ .overview-card         关键技术指标/文档统计
      │  └─ .source-details          可展开原文前言
      ├─ .section-label             完整技术文档入口
      ├─ #empty-message             搜索无结果状态
      ├─ section.chapter × N
      │  └─ .chapter-card
      │     ├─ .chapter-top          章导读
      │     ├─ .chapter-contents     H2/H3/段落/列表/表格/代码/图
      │     └─ .chapter-footer       返回总览 + 章节序号
      └─ footer.footer-page
```

**核心：全文是连续长页面，不是多路由 SPA，不跳出到多份 HTML。** 所有内容可离线查看，可在浏览器直接搜索/打印。

## 二、布局参数与设计 Token（复制自原 V2）

| 要素 | 规则 | 对应类/变量 |
| --- | --- | --- |
| 页面背景 | 淡蓝白 `#f5f7ff` | `--bg` |
| 主要文字 | 深蓝灰 `#202c4d` | `--ink` |
| 次要文字 | 蓝灰 `#727e9c` | `--muted` |
| 科技主色 | 柔和紫蓝 `#514cce` | `--primary` |
| 渐变装饰 | 淡紫 → 浅蓝 → 薄荷 | `.hero` |
| 卡片主体 | 白底、柔阴影、轻边框 | `--paper` / `--shadow` |
| 分隔线 | `#e5eaf7` | `--line` |
| 通用圆角 | `22px` | `--radius` |
| 侧边栏宽度 | 桌面 `268px`，中屏 `226px` | `.sidebar` |
| 阅读主体最大宽度 | `1290px` | `.page-inner` |
| 桌面正文左右 padding | `50px`（按屏宽自动收缩） | `.page-inner` |
| 首页 Hero | 双栏布局、圆角 `30px`、浅色渐变 | `.hero` |
| 卡片布局 | 功能卡宽屏 4 列，中屏/手机 2 列 | `.feature-grid` |
| 技术表格 | 横向可滚动，不把整页撑宽 | `.table-scroll` |
| 响应式断点 | `1220px` / `1060px` / `760px` | CSS `@media` |
| 无障碍 | 焦点边框、减少动画选项 | `:focus-visible`, `prefers-reduced-motion` |
| 打印版 | 隐藏导航/按钮，突出正文 | `@media print` |

**风格**：轻科技、卡通、柔和而清晰。中文内容优先；小图标点缀但不喧宾夺主。长正文应易读、可复制，不可用大量装饰打断阅读。

## 三、内容映射规则

| 原始 Markdown | HTML 展示 | 文字处理 |
| --- | --- | --- |
| `#` 项目标题 | Hero 项目名称 | 保留名称，允许去掉“— 技术文档”等冗余后缀；不得更名为不存在的品牌 |
| `>` 文档说明 | 首页必要提示 + 可展开原文 | 首页可简要转述，原文保留 |
| `##` 章节 | 固定章节卡 `.chapter` + 导航链接 | 章节顺序不变；如排除内部章则显示号连续重排 |
| `###` 小节 | 章内 H3 + 侧栏子目录 | 文本保持；编号随显示章节调整 |
| 段落、加粗、列表 | 原文语义 HTML | 不删关键事实，不生成新结论 |
| Markdown 表格 | `.table-scroll > table` | 逐行逐格保留，不能改数值/表头 |
| 普通 fenced code | `.code-sample` | 保留代码与空白 |
| Mermaid 图 | `.diagram-card` + `.vector-diagram` SVG + 源码详情 | 图与原始节点逐一核对，不能只放截图替代重要关系 |
| 资料声明、实现状态 | 正文保留；必要时加首页范围提示 | 区分实现 / 设计 / 未接入 / 待确认 / 已实测 |
| 内部复盘/改进清单 | 用户页默认不显示整章 | 仅过滤展示端，原文 MD 不修改；正文重要状态继续保留 |
| 章节间引用 | 在最终显示稿中修复、复核 | 防止排除章节后跳转到错误位置 |

### 首页重点提取

首页不等于缩写整篇文档，而是**读者入口**：1–2 句项目简介、2–4 张能力卡、4 步以内的真实流程、4 项以内的技术参数。无足够依据时使用“章节速览/阅读路径/文档数量”等自动可验证内容，**绝不能为了凑四张卡而编造能力或性能**。

### 内部与外部内容的边界

- 默认不单独展示“已知问题与改进建议”“内部问题清单”“缺陷清单”“研发复盘”等内部管理章节。
- 不能藉此隐藏影响事实理解的说明：例如“该功能仅预留”“测量链路尚未接入”“未开展测试”。应以**简短、中性、事实性说明**保留在相关技术章节或首页必要提示中。
- 不自动生成测试通过、性能达标、临床效果、商业认证、真实设备照片等不存在的证据。

## 四、交互能力与实现方式

- `#progress`：滚动比例指示已阅读进度。
- `.nav-chapter`：按正文标题动态生成，滚动高亮当前章，展开当前子导航。
- `#search-input`：大小写不敏感搜索章节**整体文本**；命中章节显示，未命中整章隐藏；不是逐词高亮、不是服务端全文检索。
- `#menu-btn`：屏宽 ≤760px 时显示移动导航抽屉，点击遮罩/链接后关闭。
- `#chapter-N` / `#sub-N-M`：稳定锚点，原始源文件是否编号都转换为连续显示编号。
- `.diagram-card`：仅显示与来源一致的可视化图，附 Mermaid 源码可展开以供审查。
- `.table-scroll`：表格独立横向滚动；长代码块同理。
- HTML/CSS/JS **内嵌在单个文件中**；不依赖外部 CDN。

## 五、与新项目有关的可变化部分

可以替换：项目图标/概念插画、Hero 文案、功能卡片、步骤、参数、版本、章节数和全部技术正文。不能因项目内容变化而破坏 `.sidebar`、`.page`、`.chapter-card`、`.table-scroll` 等骨架。若真有独特信息展示需求，在现有组件基础上**有限扩展**，不能推翻通用布局。

## 六、技术选择

- 模板：原生 HTML5 + CSS3 + 少量原生 JS。适合快速交付和离线文档，无需 React / Vue / Node 运行时。
- 转换脚本：Python + `markdown-it-py` + `beautifulsoup4`，用于按原文生成章节与表格，**不做技术事实推理**。
- Flow 图：优先本地 Mermaid CLI 输出 SVG，或人工核对后使用 Graphviz/SVG；输入编号依照保留章节中 Mermaid 出现顺序。
- 验证：静态锚点与章节计数由 `scripts/validate.py` 完成，最终浏览器多端视觉/交互仍需额外审查。
