# SAMPLE D｜Linux 智能交互终端的工程推导

## 与 MCU 项目的不同

功能以常驻浏览器屏保、语音、AI 问答、在线音乐、TTS、服务健康为主时，先核算 Linux 音视频和网络能力，不必加入 STM32、GPIO 与 RTOS。

## 可复用推导方法

- 浏览器：本地时钟/日期、卡片、音乐播放状态、Web Speech API TTS、交互界面。
- 后端：会话状态机、统一文字入口、AI 意图与动作白名单、天气缓存、WebSocket、健康接口。
- 音频进程：麦克风、VAD/ASR、心跳，不直接执行业务命令。
- 语音 15 秒窗口需定义唤醒、连续追问、回答/TTS 后续期、告别/取消、旧响应丢弃。
- 前端音频队列、播放限制与 TTS 焦点需区分；第三方音乐接口必须具备合法播放授权与失效降级策略。
- 开发旁路要共用同一个上层业务入口；DEV 模拟文本不伪装成真实 ASR 精度证据。

## 验收提纲

断网时屏保不白屏、文本旁路可独立运行、会话续期有效、音乐/TTS 不互相抢占、mic_loop 或外部服务单独失败时受控恢复。
