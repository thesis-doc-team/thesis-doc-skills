# 三类真实工程经验的可复用设计方法

> 匿名化观察仅用于总结方法；各示例具体硬件、参数或实现缺陷不是新项目的事实，也不是无条件的最佳实践。

## 1. 功能与硬件关系：从物理量出发

对于“人体检测”先识别对象：区域内有人（PIR/毫米波）、步数/姿态/摔倒（惯性测量 + 算法）、视觉人体识别（相机 + CV 模型），路线互斥，不能看到名称直接选型。

环境监测先列需观测的物理量，再据此选择数字总线传感器、模拟前端或 Modbus 工业传感器，必要时核对标定和量程。一般优先使用能够覆盖需求的成熟模块，不追求传感器数量。

## 2. 成熟模块复用是资源规划的组成部分

- 4G DTU 承接蜂窝网络、MQTT 重连和认证；MCU 可以只负责 JSON 等业务载荷。必须核对 DTU 是 MQTT 透传还是仅 TCP 透传。
- UART LoRa 模块负责射频收发，MCU 负责应用层协议；不能假定本机程序能配置模块的所有频点/扩频参数。
- 惯性器件 DMP/第三方驱动负责底层姿态输出，MCU 仍要实施计步/摔倒等业务判断；不能据此宣称专业识别准确率。
- Linux 多媒体终端交由 ARM64 Linux、浏览器和后端服务，不机械地引入 MCU。

## 3. 资源预算先于芯片价格或性能标签

列出每种传感器需要几个 UART、总线地址、DMA、定时器、GPIO、RAM、Flash；为按键、蜂鸣器、显示、调试、无线收发预留真实接口。选足够用的 MCU，用户有实物主控时不能擅自换芯片。数字外设够用但供电峰值不够，也属于方案不成立。

## 4. 数据分层与模拟测试

模块化不限于“每个设备一个 .c”：驱动只读硬件，数据接口向业务层提供值、有效性、最后时间戳；业务算法/告警/显示/上报消费统一的数据契约。

Mock 分两类：直接生成算法输出仅能测试下游显示/通信；生成原始姿态/串口帧经过真实算法才能验证算法路径。无硬件模拟不等于实物通过。

## 5. 任务、状态机与边沿控制

低速感知系统可用 `Init()` + `Process()` + `Tick()` 形式的裸机超级循环。用时间差节流，评估最坏阻塞时间、环形缓冲容量和错过状态变化的风险。阈值 + 边沿开关蜂鸣器只是避免重复写 GPIO；抗报警抖动还需回差或持续时间确认（仅在需求需要时引入）。

## 6. 协议是双端契约

二进制 + CRC + 包序号适合更高的数据完整性要求，ASCII 字段帧易于串口调试、轻量演示。任何选择都必须包含帧边界、字段类型、无效占位、收发双方解析、断流/多帧/旧数据状态。用户要求一对 LoRa 模块时，不能默认节点只有发送角色；必须明确页面及功能对远端数据的需求。

## 7. 从旧项目缺陷提炼不可忽略的检查

| 常见实现 | 反向规则 |
|---|---|
| 发送 `T=--`，接收却 `%f` | 非法/缺失数据必须有一致协议语义 |
| `IsValid` 只置真不超时 | 增加 `last_update` 与超时失效，避免显示陈旧值 |
| MCU UART 输出成功却软件直接置“云已连接” | 分清 DMA 完成、模组联网、服务端确认三层证据 |
| `rx_mode=DMA` 但 `HAL_UART_Receive_IT` 被调用 | 评审按实际代码路径，不按宏名推断 |
| USART 业务帧和调试日志共线 | 调试输出不得污染受严格协议约束的业务流量 |
| SHT40 使用 SHT3x 命令格式 | 核对精确芯片型号及厂家数据手册 |
| 仅有 CRC 却未校验地址/功能码 | 协议校验应覆盖与设备身份、帧类别有关的字段 |
| 固定阻塞等待收发 | 按周期与响应要求估算最坏延迟；需要时改成事件/超时状态机 |

**规则不是要求给每个项目堆全部保护机制，而是针对真实失效风险作适度选择，并留下可测试的依据。**
