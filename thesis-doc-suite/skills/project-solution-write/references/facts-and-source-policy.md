# 事实与技术来源政策

## 证据分层

| 状态 | 证据要求 | 文书表达 |
|---|---|---|
| confirmed | 用户本轮明确提出或确认 | “要求/已确认” |
| proposed | Agent 合理默认、设计推导 | “实施基线/拟采用” |
| declared | README、技术文档中的陈述 | “资料声明” |
| code_present | 实际读取代码、可追踪函数与调用点 | “代码中存在该路径”，不是实测通过 |
| mock | Mock 样例、假数据、模拟仿真 | “模拟/测试桩”，不是实测 |
| tested | 对应真实设备的日志、报告、运行截图或明确记录 | “已在……条件下验证” |
| unknown | 冲突/未获得证据 | “待核实，未验证” |

## 来源层级

具体芯片/模块以厂家规格书/数据手册优先；开发接口/服务以官方技术资料为准；标准协议以原标准或可信厂商资料为准；CSDN、论坛、GitHub issue 可以辅助排障但不能替代官方测量指令或作为精度证明。用户指定的既有代码事实比推测优先，但若与官方规范冲突要明确分开陈述，而不是改写源码。

至少核查：**部件型号与封装、供电/电平、硬件接口、测量命令/CRC、数据换算、合法通信频段、实际 API 路径/权限、外部服务费用或可用性（仅真正影响实施时）**。

没有联网能力或来源不可得时，不制造来源链接；把依赖写为需要依据实物确认的条件，不把它描述为已核对。

## 源码读取限制

只分析用户明确提供的仓库目录与文件；不扫描其他无关目录，不读取/输出 `.env`、凭证或密钥。源码中 `#if 0`、空回调、未被调用函数需标出未接入状态。报告中的代码引用要尽可能给文件、符号及行号（若有）。
