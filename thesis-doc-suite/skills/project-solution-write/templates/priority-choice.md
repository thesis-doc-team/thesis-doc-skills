# 设计方向选择（聊天用，禁止混入正式项目文档）

**先确认题目和功能是否已具备。** 二者缺一时按 `initial-intake-message.md` 问缺失内容，附带一次本四选项即可；不得只问侧重而遗漏项目题目和功能。

在题目与功能已具备时，设计侧重只询问一次；用户已有偏好或说“直接生成”则不要重复询问：

> 我会负责具体技术选型。你希望这个项目首先优化哪方面？**① 成本优先**（在满足必需功能前提下压低硬件和后续使用总成本）；**② 性能优先**（重点保障响应速度、精度、稳定性等本项目关键指标）；**③ 功能优先**（让已提出的功能与交互尽可能完整，不新增功能）；**④ 均衡方案**（兼顾成本、性能、功能与开发难度）。若无特别偏好选④；预算上限或关键指标可以顺带告诉我。

若同时存在可能导致根本性选型错误的重大功能歧义，在同一轮提出不超过 1～3 个聚合问题；**不要**为 UART、DMA、ACK、引脚、品牌等普通实现细节反复向用户发起选择。

用户说“直接做/别问/按照你判断”，按均衡方案（`proposed`）执行；不得将拟定偏好写成用户已确认。
