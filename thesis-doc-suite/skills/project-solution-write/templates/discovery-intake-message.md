# 毕设/课程设计选题入口对话示例（仅聊天，不作为项目文件）

**用户什么都没提供，默认入口：**

> 你想找什么方向的毕设/课程设计题目？专业、技术偏好、已有的开发板或传感器都可以直接告诉我——信息越完整，推荐的题目越准。我会控制在单板、现成模块的规模内，每个候选至少 7 条完整闭环功能和一个具体应用场景；题目会先向上泛化到“场景+核心能力”，再按题目发散出具体功能，不要求你自绘 PCB 或做大型部署。默认只做选题；如果你之后确定题目并明确要求，才进入正式方案。

**只知道专业：**

> 我会根据你的专业先展示几类不同的项目方向（农业、仓储、医疗、家居……），再推荐具体候选。你也可以告诉我必须用哪些技术、手头有什么开发板或传感器。

**到过技术关键词：**

> 我会结合你的专业和技术基础推荐项目。STM32（或其它技术）是必须使用的硬约束，还是你学过/倾向用的技术？只有这个区别影响推荐时才问。

**已有大致想法但不确定：**

> 我可以围绕这个想法生成几个不同的候选及核心功能。如果只是想先看看有什么选项，不必立刻确定。

**用户确认题目和功能、要求写正式方案：**

> 现在如果确定题目与功能，就可以进入正式方案——生成《项目介绍与功能说明》MD+HTML 和《工程实施方案》MD。你也可以继续做候选、拒绝或修改。

**用户看上某题：**

> 我保留这个项目的 ID 与当前版本。你可以加功能、改功能或拒绝；如果想“更丰富”，我先给若干具体功能供确认，确认后再更新三份候选文件。

始终只问真正阻止下一步的内容。**禁止强制用户一次性填完整表格**，已有的信息不重复问。**不主动询问经费或工期**，只通过“单板、模块化、不画电路板、小规模可验证”来表达规模边界。
