一个插件，六种毕业设计文书；一个项目，一套共享资产。

Thesis Doc Suite Taru（thesis-doc-suite）把技术文档、任务书、开题报告、文献综述、指导记录、中期检查六种文书生成能力整合为一个 Claude Code 插件：官方 Word 模板原位填写、参考文献真实核验、逐页截图检查，项目数据只录一次、跨文书复用。

SKILL 功能展示

10 个 Skill，各司其职，独立可调

6 个业务 Skill 负责文书生成，1 个支持 Skill 管公共视觉素材，3 个管理 Skill 负责项目初始化、检查与导航。每张卡片直接展示完整说明。

业务 Skillv5.2.0

project-technical-doc

项目技术文档生成：只读理解真实项目 → 带证据的 MD 技术文档 → 派生离线 HTML 展示站。

可以生成什么

完整 Markdown 技术文档、单文件离线 HTML 用户展示网站，并沉淀可复用的项目技术事实（FACT-xxx）。

需要哪些输入
  • 项目源码或技术资料（MD/DOCX/PDF 等）必需
  • 项目根目录 <PROJECT_ROOT>必需
  • 展示配置.json、已有 project-assets 事实库可选
最终输出什么
  • <项目名>-技术文档.md、<项目名>_用户展示.html、执行汇报.md
  • 项目事实与证据台账.md（大型项目）
  • 保存位置：deliverables/technical-document/
使用场景

需要把一个真实项目整理成可交付的技术说明文档和展示网页时。

运行命令
/thesis-doc-suite:project-technical-doc
必要前置条件
  • Python 3.10+
  • markdown-it-py、beautifulsoup4（HTML 派生）
  • 无需官方 Word 模板

SKILL 关系图

技术资料 → 共享项目事实 → 文档生成

所有 Skill 通过同一个项目资产包关联：上游沉淀的事实与文献，下游直接复用。

不必依次完成所有文档！各 Skill 可独立调用，只有「真实项目技术资料」是共同必需输入；技术文档是推荐的起点（它沉淀的 FACT-xxx 技术事实能让后续文书少走弯路），但不是硬性前置。
实线＝必需依赖 / 提炼事实 紫色细线＝共享资产复用 虚线＝推荐顺序（非强制） 点线＝独立调用时的直接输入
边界规则每个 Skill 只生成自己的文书：任务书 Skill 不会顺带写出开题报告，中期检查也不会重写技术文档。跨文书的共享只发生在 project-assets 数据层。
统一资产管理

一个项目 = 一个资产包

数据区 + 成品区 + 运行区。同一信息只录一次，所有文书共用；项目之间完全隔离。

数据区 · project-assets/

project.json · facts.json · references.json schedule.json · progress.json · activity.jsonl
  • 项目身份与人员元信息（project.json）
  • FACT-xxx 技术事实：结论 + 来源 + 确认状态
  • REF-xxx 文献库：稳定编号 + 核验记录
  • 统一周计划：原计划 / 变更 / 实际进展分开
  • activity.jsonl：每次变更与成品登记的审计流水

成品区 · deliverables/

technical-document/ taskbook/ opening-report/ literature-review/ guidance/ midterm/
  • 正式交付成品按文书类型分目录存放
  • 文件名自带版本号：…-v1 / -v2 / -v3
  • 新版本新文件，永不覆盖、永不删除历史版本
  • 每版单独登记使用记录（路径 + SHA-256）
  • 一目录看全一个项目的所有产出

运行区 · .skill-tmp/

.skill-tmp/<skill-name>/<run-id>/
  • 渲染截图、结构审计 JSON、草稿中间件都放这里
  • 每个运行目录带所有权标记，互不干扰
  • 运行结束自动清理本轮临时文件
  • 清理只限本 Skill 自己的运行目录
  • 绝不触碰原始资料、官方模板、共享资产和正式成品
FACT-xxx

技术文档 Skill 核实并入库，任务书 / 开题 / 中期按稳定 ID 引用同一事实，状态口吻（已实现 / 声明 / 设计 / 待确认）全链路保持一致。

REF-xxx

一篇文献只检索核验一次。任务书用 10 篇、综述用其中 8 篇，正文编号各自重排，但都指向同一个稳定 ID 与核验记录。

周计划

任务书拟定的周计划基线被开题报告复用；中期检查对照它写实际进展——计划归计划、实际归实际，不混为一谈。

为什么不需要重复录入？项目名称、技术架构、器件选型、文献、进度——这些信息在第一次使用时写入 project-assets/，之后任何文书 Skill 读到的都是同一份。需要修改时必须提供依据并显式更新（--replace --reason），系统绝不静默覆盖已确认的数据。
使用流程

新手引导：从零到第一份文书

八个步骤，每步都有明确操作。走完一遍即可独立使用全部 Skill。

1

准备环境

安装 Python 3.10+ 与依赖（python-docx、lxml、PyMuPDF）；Word 文书的逐页截图检查需要 LibreOffice 或 Word 兼容渲染器。只有技术文档 / 管理 Skill 时可暂缓 LibreOffice。

2

加载插件

在 Claude Code 中指向插件目录启动；看到 10 个 /thesis-doc-suite:… 命令即加载成功。

claude --plugin-dir "E:\Code\thesis-doc-suite"
3

初始化项目资产包

为你的毕业设计项目创建唯一资产包（数据 + 成品 + 运行区骨架），project_id 一经建立不再更改。

/thesis-doc-suite:init-project
4

导入技术资料

把项目源码目录、技术手册、需求文档等放入项目位置并告知 Claude；推荐先跑技术文档 Skill，沉淀 FACT-xxx 技术事实。

/thesis-doc-suite:project-technical-doc
5

检查前置条件

按 PASS / WARN / BLOCK 确认环境、模板哈希与资料齐备度；缺什么、能不能降级执行一目了然。

/thesis-doc-suite:check-project
6

选择要生成的文书

按当前需要挑一个业务 Skill，不必按固定顺序；不确定就用 /thesis-doc-suite:help。

/thesis-doc-suite:thesis-taskbook-write
7

生成文档

Skill 自动完成：读共享资产 → 复用/补充文献 → 官方模板副本填充 → 结构校验 → 逐页截图检查 → 输出执行汇报。中间文件留在运行区并自动清理。

8

查看报告和成品

成品在 deliverables/<文书类型>/，执行汇报列出检查结果、待确认事项与 WPS 实测边界；最终内容由你和指导教师验收。

前置准备清单

开跑前要准备什么？

分清必需与可选——不必把所有材料都提前备齐，缺可选项也能降级执行。

软件环境

  • 必
    Python 3.10+（python-docx、lxml、PyMuPDF、markdown-it-py、beautifulsoup4）
  • 必
    Claude Code（或其他本地 Agent）+ 本插件
  • 必
    LibreOffice 或 Word 兼容渲染器（Word 文书逐页截图检查）
  • 选
    WPS 客户端（仅用于最终人工复核，未实测会如实标注）

项目技术材料

  • 必
    项目源码或技术资料至少一种（MD / DOCX / PDF / 仓库目录）
  • 选
    测试记录、协议文档、原理图 / BOM、部署说明
  • 选
    既有 project-assets 资产包（老项目复用）

官方模板

  • 必
    对应文书的学校官方空白 DOCX（插件已内置塔里木大学版本只读副本 + 哈希锁）
  • 选
    你手上的新版官方模板（提供后以新模板为准，先审计再适配）
  • 选
    已填写范本（仅学写法，不继承任何个人信息）

参考文献

  • 必
    任务书 / 开题报告：≥10 篇真实可核验文献（知网、万方、维普等）
  • 必
    文献综述：默认 ≥8 篇（以学校要求为准）
  • 选
    已有文献清单 / DOI / 链接（复用 REF-xxx，免重复检索）

项目信息

  • 必
    课题题目（可从技术资料拟稿，执行汇报会标注）
  • 选
    姓名 / 学号 / 学院 / 专业 / 班级 / 导师 / 职称（未知留空，不套用他人信息）
  • 选
    起止日期、当届工作安排

计划与进度

  • 必
    中期检查：计划与实际进展的真实证据（否则只出待核实草稿）
  • 选
    统一周计划基线（缺失时按真实安排拟 draft，确认后才标 confirmed）
  • 选
    指导记录的真实时间 / 地点 / 方式（缺失一律留空）
可选资料缺失时Skill 会降级执行并在执行汇报中明确说明影响（如「未核实源码，仅依据资料声明」），而不是直接拒绝或编造内容。
命令与实际操作

真实可用的命令速查

以下均为实际实现的命令。命令示例是「命令形状」，项目路径与 ID 需替换为你自己的。

① 本地加载插件（Windows 示例）

claude --plugin-dir "E:\Code\thesis-doc-suite"
claude plugin validate "E:\Code\thesis-doc-suite"

把路径换成你解压/克隆插件后的实际目录。出现 10 个 /thesis-doc-suite:… 命令即加载成功。

② 九个斜杠命令

/thesis-doc-suite:init-project
/thesis-doc-suite:check-project
/thesis-doc-suite:project-technical-doc
/thesis-doc-suite:thesis-taskbook-write
/thesis-doc-suite:opening-report-writer
/thesis-doc-suite:literature-review-write
/thesis-doc-suite:thesis-guidance-record-write
/thesis-doc-suite:thesis-midterm-check-write
/thesis-doc-suite:help

③ 项目资产命令行（进阶 / 脚本化）

python scripts/check_env.py
python core/asset-management/project_assets.py init --root "E:\MyThesis" --project-id my-thesis-2026 --name "我的毕业设计"
python core/asset-management/project_assets.py status --root "E:\MyThesis"

以上命令在插件安装目录下执行；<PROJECT_ROOT> 指向你的项目资产包根目录（存放 project-assets/ 与 deliverables/ 的那一层），不是插件安装目录。

常见问题

遇到问题先看这里

八个高频问题的答案；仍无法解决时用 /thesis-doc-suite:check-project 生成检查报告定位原因。

Q为什么 Skill 没加载？▾
确认插件目录指向的是含 .claude-plugin/plugin.json 的根目录（Windows 路径含空格/中文时建议加引号）；重启 Claude Code 后在输入框键入 /thesis-doc-suite:，应出现 10 个命令的自动补全。仍不出现时运行 claude plugin validate 检查清单结构，或执行 /thesis-doc-suite:check-project（若该命令也没有，请检查插件是否加载）。
Q为什么缺少模板？▾
Word 文书 Skill 依赖学校官方空白 DOCX 及其哈希锁（template-lock.json）。插件已内置塔里木大学版本只读副本；如果你的学校使用不同模板，请提供官方空白 DOCX——Skill 会先做只读结构审计再适配填写位置，绝不修改模板原件，也不会拿旧模板冒充新模板。技术文档 Skill 不需要 Word 模板。
Q为什么不能自动生成某些内容？▾
凡是需要真实性的内容——指导教师评价、签名、真实会面日期、已完成的测试结果、未核实的文献——都不会自动生成或编造。教师意见栏输出的是「供教师审定的拟稿」，签字与日期留空；文献查不到就标 verified=false。这是防止学术不端的硬性设计，不是功能缺陷。
Q为什么参考文献需要核验？▾
参考文献必须真实可查：优先知网、万方、维普、期刊官网、学位论文库、Crossref/DOI 等可核验来源，每条记录来源链接与核验时间。CSDN 等技术社区只能作为标注了真实类型的辅助资料，不能冒充期刊论文。无法核实的条目会显式标注，绝不伪装成已核实文献。
Q如何复用已有项目？▾
项目的一切持久数据都在项目资产包（<PROJECT_ROOT>/project-assets/）里。换机器或换会话时，只要把项目目录带过去、在调用 Skill 时指向同一个 <PROJECT_ROOT>，FACT-xxx 事实、REF-xxx 文献、周计划、成品历史（deliverables/ 下的 -vN 文件）全部自动可复用，无需重新检索和录入。
Q如何修改项目资产？▾
已有资产不会被静默覆盖：更新必须提供实际证据和变更原因（命令行对应 --replace --reason），并写入 activity.jsonl 审计流水。项目 ID 不一致时系统直接拒绝合并，防止串项目。普通个人信息（姓名、学院等）可在 project.json 元信息中更新。
Q如何避免覆盖正式文档？▾
成品文件名自带版本号（…-v1 / -v2 / -v3），重新生成永远新建下一个版本文件，历史版本永不覆盖、永不删除；输出路径已存在时脚本直接拒绝写入。官方模板永远只读，所有填写都发生在副本上。
Q如何查看生成文件？▾
打开 <PROJECT_ROOT>/deliverables/，按文书类型子目录（technical-document / taskbook / opening-report / literature-review / guidance / midterm）分门别类；同目录的执行汇报记录了生成路径、检查结论、待确认事项与 WPS 实测边界。技术文档 Skill 还会输出可双击浏览的离线 HTML。
