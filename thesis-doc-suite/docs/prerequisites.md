# 前置条件清单（Prerequisites）

按"**必需 / 可选**"列出使用本插件需要准备的东西。原则：**缺可选项允许降级执行（并声明影响），只有确实影响可靠执行的关键缺失才阻止操作（BLOCK）**——不是所有材料都要提前备齐才能开始。

自检工具：

```bash
python scripts\check_env.py --root "E:\thesis-work\env-monitor" --skill thesis-taskbook-write
```

输出按 **PASS / WARN / BLOCK** 三类展示（WARN = 可继续但可能降低完整度或质量；BLOCK = 关键条件不足，不能可靠执行）。

---

## 1. 软件环境

| 项目 | 必需性 | 说明 |
|---|---|---|
| Claude Code | **必需** | 插件宿主；`claude --plugin-dir` 或 marketplace 加载 |
| Python 3.10+ | **必需** | 全部脚本运行环境（Windows/macOS/Linux，Windows 优先适配） |
| python-docx、lxml | Word 文书**必需** | 读写 DOCX：`python -m pip install python-docx lxml` |
| PyMuPDF | Word 文书**必需** | DOCX → 逐页 PNG/PDF 渲染 |
| markdown-it-py、beautifulsoup4 | 技术文档 HTML **必需** | `python -m pip install markdown-it-py beautifulsoup4` |
| LibreOffice（或等价命令行渲染器） | **强烈建议** | 逐页截图验证分析的渲染引擎；缺失时报"截图验证分析未完成"，需人工核对排版 |
| WPS / Microsoft Word | 可选 | 用户最终目视验收；未实际打开过不得声称"WPS 已验证" |
| Mermaid CLI / Graphviz | 可选 | 技术文档 HTML 的流程图转 SVG（缺失时保留 Mermaid 源码回退） |
| 管理员权限/开发者模式 | 可选 | Windows 创建符号链接用（仅安全测试需要，不影响正常使用） |

一键安装核心依赖：

```bash
python -m pip install python-docx lxml PyMuPDF markdown-it-py beautifulsoup4
```

## 2. 项目技术材料

| 材料 | 必需性 | 用途 |
|---|---|---|
| 项目技术手册 / 需求 / 设计文档（MD/DOCX/PDF） | **必需**（与源码二选一或都有） | 一切文书内容的事实来源 |
| 项目源码 / 工程目录 | 可选（有则更强） | 佐证"已实现"，提炼 FACT |
| 测试记录 / 实验数据 / 现场照片 | 可选 | 区分"已实现"与"实测通过"的唯一依据 |
| 接口协议 / 硬件资料 / BOM | 可选 | 技术文档、任务书的深度细节 |

资料不完整时：先完成可证实部分，缺口在执行汇报中列"待确认"；**不拿模板/范本编造内容**。

## 3. 官方模板

| 材料 | 必需性 | 说明 |
|---|---|---|
| 官方空白 Word 模板 DOCX | Word 文书**必需**（已内置只读副本） | `skills/<skill>/assets/official-*-template.docx` + `template-lock.json` 哈希锁 |
| 学校新版官方模板 | 可选（有则以此为准） | 提供后 Skill 重新审计、重建填写坐标；**不修改你的原件** |
| 已填写参考范本 | 可选 | 内置去标识化范本已够用；只学写法不借事实 |
| 技术文档 Skill | **无需模板** | 内置通用技术文档范本 + HTML 布局 |

## 4. 参考文献

| 项目 | 必需性 | 说明 |
|---|---|---|
| ≥10 篇真实可核验学术文献 | 任务书、开题报告**必需** | 原模板要求"不少于10篇"；优先知网/万方/维普/期刊学位论文库/Crossref-DOI |
| 默认 ≥8 篇独立真实文献 | 文献综述**必需**（数量服从学校要求） | 不为凑数造文献 |
| 文献支持 | 中期检查/指导记录**非必需** | 这两类官方表无参考文献栏；仅在需外部佐证时检索 |
| 已核验文献库（REF-xxx） | 可选 | 有则跨文书复用，不重复检索 |

**硬规则**：文献不得伪造；无法核实的条目标 `verified=false` 并显式披露；CSDN 等博客只能作标注类型的技术补充。首次生成前可先在知网/万方等检索并记录 URL 与核验时间，减少往返。

## 5. 项目信息

| 字段 | 必需性 | 缺失时的行为 |
|---|---|---|
| 项目根目录 `<PROJECT_ROOT>` | **必需** | — |
| 稳定 `project_id`、项目名称 | **必需**（init 时确定） | — |
| 课题题目 | 任务书**必需**（可从资料拟稿，需标明） | 其余文书从资料提取 |
| 姓名/学号/学院/专业/班级/导师/职称 | 可选 | **一律留空**，不从范本继承他人信息 |
| 起止日期 / 检查日期 | 可选 | 保留官方日期占位并列待填写；不套用旧范本日期 |

## 6. 计划与进度信息

| 项目 | 必需性 | 说明 |
|---|---|---|
| 周计划基线（schedule.json） | 可选 | 没有则由任务书 Skill 起草 `draft` 基线；`confirmed` 需真实确认 |
| 实际进展证据（progress.json / 测试记录） | 中期检查**实质必需** | 无充分证据时产"待核实草稿 + 缺口清单"，不冒充实绩 |
| 真实指导记录（时间/地点/方式/评价） | 指导记录可选 | 缺失一律留空、不编造会面 |

## 7. 各业务 Skill 要求速查

| Skill | 硬门槛（不足则无法可靠生成） | 软门槛（缺则降级并声明） |
|---|---|---|
| project-technical-doc | 项目资料/源码至少一种 | 展示配置、实测数据 |
| thesis-taskbook-write | 技术资料 + 官方模板 + 题目 + ≥10 篇核验文献 | 个人信息、起止日期、范本 |
| opening-report-writer | 技术文档 + 官方模板 + ≥10 篇核验文献 + 正文≥3000字 | 封面信息、共享计划 |
| literature-review-write | 技术资料 + 官方模板 + ≥8 篇核验文献 + 正文≥2500字 | 封面信息、综述范本 |
| thesis-guidance-record-write | 技术资料 + 官方模板 + ≥8 个真实指导主题 | 真实指导时间/方式/评价 |
| thesis-midterm-check-write | 技术资料 + 官方模板 + 三栏各≥200字的真实内容 | 检查日期、进展快照、计划基线 |
