# 文献综述范本逆向统计｜可复用写作和版式规则

**依据**：用户最初四份完成范本的已脱敏副本（`assets/reference-samples/sample-*.docx`）及本次真正官方空白模板（`assets/official-literature-review-template.docx`）。统计脚本：`scripts/inspect_reference_styles.py`；原始格式频次：`references/sample-style-audit.json`。

## 一、硬格式与软风格分离

1. 官方硬要求：正文 2500 字以上、五号宋体、1.5 倍行距，英文/罗马字符 Times New Roman；学校封面、两节、正文跨页两行一列表格、指导教师审阅栏、签名/日期原位保留。**哪怕四份范本的多数写法与官方冲突，也不能动官方不变区域。**
2. 范本共同叙事：3/4 使用“引言—国内外研究现状—评述”的前三章；另 1/4 使用“研究背景—国内外研究现状—设计内容”，不能据此将文献综述改成技术设计说明书。
3. 多数范本教师评语使用“该生 + 文献检索与理解 + 理解课题背景与现状 + 能结合选题分析 + 后续评价”，四份均保留教师审阅栏目；输出须标注是供指导教师审核的拟稿，不得冒认已签署。
4. 段落视觉：主章标题前不强加个人喜好的空行，正文一般首行两字符，引用上标，文后参考文献以 `[1]` 顺序列出。范本中存在实际缩进不一致和不完整著录，**不能复制这些缺陷**。
5. 自动统计结果：四份范本主章标题共观察到 12 段，均显式1.5倍行距；教师意见首行缩进有设置与未设置两类；一些历史文件段落属性为 `None`（可能继承样式），所以**不应用 `None` 当作格式标准**；最后采用官方要求、正文的稳定统一设置，而非机械复制多数值。

## 二、通用写作思维与质量上限

1. 背景论证：明确谁受到什么影响 → 现有处理方式的缺陷是什么 → 为什么值得做这个题目。
2. 研究现状：按 2～4 个真正相关的技术主题与有证据的论文对照，说明方法/部署条件/取得的结果/局限，避免“国外先进、国内落后”的空泛句子。
3. 文献评述：从证据出发归纳可借鉴点、场景差异、尚待验证的工程问题；不把系统技术手册的模块清单逐条换一种说法。
4. 参考文献：文内首次出现的稳定 `REF-ID` 分配本轮连续 `[1]…`；完整数据来自已核验的共享 `references.json`；CSDN 可用于工程实现背景但不能冒充学术期刊。
5. 教师评语：只能评价实际写出的文献综述，不预判学生已完成的硬件测试或老师已经通过；签字日期不填。

## 三、历史缺陷的反面规则（硬性测试覆盖）

- 不能通过 `Document()` 另造学校封面；不能改表格网格/页边距/教师签字区；模板 SHA 不匹配停止填充。
- 不依赖普通空格生成长下划线；在原段落填充制表位，**仍必须实际截图检查是否上下碰撞或左右长短不一**。
- 文内 `[n]` 使用 Word `superscript=True`，文献列表正常基线；不能用 Unicode 假上标；必须严查 `[1,2]`、`[1-3]` 引用范围。
- 禁止复制样本的数字、原项目硬件、个人身份、错误参考文献、重复文本与失效交叉引用字段。
- 在跨页表格中“标题与下文同页”属性可能被 Office/LibreOffice 忽略；出现孤立标题必须重新布局、再渲染，不把程序 PASS 当视觉 PASS。

## 四、样本之间的求同存异决策

**官方明确要求 > 本次用户明确修改 > 四份样本一致观察 > 学术写作规范 > Agent 的保守推断。**

冲突如仅涉及写法，可依文献综述的目的判断；如涉及官方固定结构、示例私人资料或尚未明确的学术事实，禁止擅自决定。出于稳定性，新增自定义模板必须单独建立 mapping/lock/测试，不得偷偷沿用此版固定段落索引。
